# 4-1-(나) 운영 영역 신규 Agent 확대

## 설계 원칙: 공통 데이터 기반 Agent 구조

본 과제의 운영 영역 신규 Agent는 개별 기능의 집합이 아니라, **두 개의 공통 데이터 축** 위에 올라가도록 설계한다. 이를 통해 Agent가 확장될수록 데이터 자산 가치가 누적되며, 성과측정 체계(4-4)와도 동일한 데이터 파이프라인을 공유한다.

```
[기개발 운영 Agent]                         [신규 운영 Agent]              [성과측정 체계]
(문의대응·데이터추출·모니터링 등)                                              (4-4)
         │                                                                   ▲
         │  ┌───────────────────────────┐    ┌─────────────────────┐       │
         ├─▶│  운영 실적 데이터           │───▶│ SLA 관리 Agent      │───────┤
         │  │  (모니터링·티켓·처리이력)    │    │ 운영 리포트 Agent    │       │
         │  └───────────────────────────┘    └─────────────────────┘       │
         │                                                                   │
         │  ┌───────────────────────────┐    ┌─────────────────────┐       │
         └─▶│  운영 지식 데이터           │───▶│ 운영 개선 Agent     │       │
            │  (장애·문의·변경이력·매뉴얼) │    │ 운영 지식 Agent     │       │
            └───────────────────────────┘    └─────────────────────┘       │
```

**이 구조의 효과:**

- 기개발 Agent는 단순 고도화에 머무르지 않고 **데이터 Producer**로 재정의됨
- 신규 Agent들이 동일 데이터를 공유하여 **중복 파이프라인 구축 없음** (Minimize)
- Agent 간 데이터 흐름이 표준화되어 **Orchestration의 기반이 됨** (Connect)
- 운영 실적 데이터가 그대로 성과측정 입력으로 연결됨 (Measure)

---

## A. 운영 실적 데이터 기반 Agent

### A-1. SLA 관리 Agent _(서비스 수준 관리 영역, 비중 3%)_

**목적:** SLA 지표의 실시간 집계·분석·예측을 통해 서비스 수준 관리 업무를 자동화한다.

**주요 기능:**

- 운영 실적 데이터 기반 SLA 달성률 자동 집계 (실시간·주기적)
- 이력 데이터 학습 기반 SLA 미달 **리스크 사전 예측**
- 미달 발생 시 관련 로그·티켓 **상관분석 리포트 자동 생성**

**입력:** 모니터링 지표, 티켓 처리 이력, SLA 정의 **출력:** SLA 대시보드, 리스크 알림, 원인 분석 리포트 → 성과측정 체계(4-4)로 연결 **기대 효과:** 수작업 집계 업무 감소, SLA 미달 선제 대응

---

### A-2. 운영 리포트 Agent _(업무회의/보고 영역, 비중 6%)_

**목적:** 운영 현황을 정기/비정기 보고서 형태로 자동 생성한다.

**주요 기능:**

- 주간·월간 운영 보고서 **드래프트 자동 생성** (운영 실적 데이터 기반)
- 회의체 목적·참석자 유형에 따른 **보고 포맷 커스터마이즈**
- 회의록 요약 및 **액션 아이템·이슈 자동 추출**

**입력:** 운영 실적 데이터 (A-1과 동일 소스), 회의 컨텍스트 **출력:** 보고서 드래프트, 회의록 요약, 액션 아이템 **기대 효과:** 보고 문서화 업무 자동화, 보고 품질·일관성 확보

---

## B. 운영 지식 데이터 기반 Agent

### B-1. 운영 개선 Agent _(업무지원 영역, 비중 2%)_

**목적:** 운영 이력 데이터를 분석하여 개선 포인트를 능동적으로 발굴한다.

**주요 기능:**

- 장애·문의 이력의 **패턴 분석 기반 개선 과제 자동 발굴**
- 반복 발생 이슈에 대한 **근본원인 후보 제시**
- 운영 환경 구축·유지 가이드 **자동 생성·업데이트**

**입력:** 장애·문의·변경 이력, 운영 환경 설정 정보 **출력:** 개선 과제 후보 리스트, 원인 분석 리포트, 환경 구축 가이드 **기대 효과:** 사후 대응에서 **선제 개선**으로 운영 품질 패러다임 전환

---

### B-2. 운영 지식 Agent _(교육 영역, 비중 1%)_

**목적:** 운영 지식을 학습·전달 가능한 형태로 구조화하여 교육·온보딩을 지원한다.

**주요 기능:**

- 시스템 변경 이력·릴리즈 노트 기반 **교육 자료 드래프트 자동 생성**
- 운영 매뉴얼 기반 **자연어 Q&A 응답** (신규 운영자 온보딩)
- 교육 이수 현황 관리 및 **학습 경로 추천**

**입력:** 운영 매뉴얼, 릴리즈 노트, 변경 이력 (B-1과 동일 소스) **출력:** 교육 자료, Q&A 응답, 학습 가이드 **기대 효과:** 신규 운영자 온보딩 기간 단축, 지식 전수 체계화

---

## 기개발 Agent의 역할 재정의

RFP에 기개발된 운영 Agent(문의대응·데이터 추출·모니터링 등)는 본 과제에서 단순 고도화에 머무르지 않고 **운영 실적·운영 지식 데이터의 Producer**로 재정의된다.

|기개발 Agent 영역|생성되는 데이터|소비하는 신규 Agent|
|---|---|---|
|문의대응|문의 이력, 처리 시간|SLA 관리, 운영 리포트, 운영 개선|
|데이터 추출|요청 패턴, 처리 이력|운영 리포트, 운영 개선|
|모니터링|알람 이력, 조치 이력|SLA 관리, 운영 리포트, 운영 개선|

이 재정의를 통해:

- 기개발 Agent 고도화 방향이 **"데이터 생성 품질 향상"** 이라는 명확한 기준을 갖게 됨
- Agent 간 연계(MCP/A2A)의 **표준 인터페이스가 데이터 계약(Data Contract)** 형태로 정형화됨

## 성과측정 체계(4-4)와의 연결

A군 Agent(SLA 관리·운영 리포트)의 출력은 성과측정 체계의 **핵심 입력**이다. 이로써 성과측정이 별도 체계가 아니라 운영 Agent 파이프라인의 **자연스러운 귀결**이 된다.
