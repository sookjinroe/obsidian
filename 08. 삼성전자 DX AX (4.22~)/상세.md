# 4-1-(나) 운영 영역 신규 Agent — 영역별 상세

각 영역별로 다음 구조로 기술한다:

- **세부 액티비티 분해** — 업무 단위별 As-Is / To-Be / 실행방안 / 목표수준
- **Agent 내부 구성** — 기능 모듈
- **Agent 간 연계** — 4-1·4-2·4-4와의 연결
- **영역 전체 목표수준**

---

## A-1. SLA 관리 Agent

**대응 업무 영역:** 서비스 수준 관리 (RFP 3.4 비중 3%)

**Agent 역할:** 운영 실적 데이터를 기반으로 SLA 지표를 자동 측정·분석·예측하여, 수작업 중심의 서비스 수준 관리 업무를 능동형 체계로 전환한다.

### 세부 액티비티 분해

|세부 액티비티|As-Is|To-Be|실행방안|목표수준|
|---|---|---|---|:-:|
|SLA 지표 수집·집계|운영자 수작업 집계|Agent 실시간 자동 집계|운영 실적 데이터축 기반 집계 엔진. 계약 기준 SLA 정의서를 구조화 데이터로 관리.|**80~90%**|
|SLA 달성률 분석|주기적 수작업 분석|실시간 대시보드 자동 제공|달성률·추세·임계치 이탈 자동 시각화. 이상 구간 자동 하이라이트.|**70~85%**|
|SLA 보고서 작성|운영자 보고서 수작업 작성|Agent 드래프트 생성 + 운영자 검수|보고 템플릿 기반 자동 생성. 운영자 주석·결재만 추가.|**60~75%**|
|미달 리스크 대응|사후 원인 분석|사전 예측 + 원인 후보 제시|이력 학습 기반 미달 리스크 예측 모델. 티켓·로그 상관분석으로 원인 후보 자동 도출.|**40~60%**|

### Agent 내부 구성

- **집계 엔진:** 운영 실적 데이터 수집·정제·계산
- **예측 모듈:** SLA 미달 리스크 사전 알림 (이력 기반 학습)
- **분석 모듈:** 미달 발생 시 관련 티켓·로그 상관분석
- **리포팅 모듈:** 대시보드·보고서 드래프트 생성

### Agent 간 연계

- **기개발 Agent (Producer):** 문의대응·모니터링·조치가이드 Agent의 실행 이력을 입력으로 수용
- **A-2 운영 리포트 Agent:** SLA 측정 결과를 보고서 입력으로 전달
- **4-4 성과측정 체계:** SLA 달성 이력이 ITO 정산 근거로 직접 연결
- **4-2 Orchestration:** 미달 리스크 발생 시 관련 Agent(예: 운영 개선 Agent) 자동 트리거

### 영역 전체 목표수준: **65~80%**

## A-2. 운영 리포트 Agent

**대응 업무 영역:** 업무회의/보고 (RFP 3.4 비중 6%)

**Agent 역할:** 운영 실적·이력 데이터를 기반으로 정기·비정기 보고 산출물을 자동 생성하여, 운영 인력의 문서화 부담을 경감하고 보고 품질의 일관성을 확보한다.

### 세부 액티비티 분해

|세부 액티비티|As-Is|To-Be|실행방안|목표수준|
|---|---|---|---|:-:|
|정기 보고서 작성|운영자 수작업 작성 (주간·월간)|Agent 드래프트 생성 + 운영자 검수|회의체별 보고 포맷 템플릿 구축. 운영 실적 데이터 자동 반영.|**60~75%**|
|회의 자료 준비|회의별 별도 자료 작성|기존 보고서·실적 데이터에서 자동 추출·재구성|회의 목적·참석자 유형에 따른 포맷 커스터마이즈.|**50~70%**|
|회의록 작성|참석자가 수작업 작성|Agent 자동 요약·구조화|회의 음성/채팅/문서 입력 기반 요약. 액션 아이템·이슈 자동 추출.|**50~70%**|
|이슈·액션 아이템 관리|별도 파일로 관리|Agent가 회의록에서 자동 추출·트래킹|회차 간 액션 아이템 상태 추적. 미처리 항목 알림.|**60~80%**|
|임시 보고 대응|요청 시 수작업 작성|자연어 요청 → Agent 리포트 자동 생성|임시 질의에 대해 구조화된 리포트 즉시 생성.|**40~60%**|

### Agent 내부 구성

- **템플릿 관리 모듈:** 회의체·보고서 유형별 포맷 관리
- **데이터 어그리게이션:** 운영 실적 데이터 기반 지표 자동 반영
- **요약·추출 엔진:** 회의록 요약, 액션 아이템 추출
- **트래킹 모듈:** 이슈·액션 아이템 상태 관리

### Agent 간 연계

- **A-1 SLA 관리 Agent:** SLA 측정 결과를 보고서에 자동 반영
- **B-1 운영 개선 Agent:** 개선 과제 발굴 결과를 보고 항목으로 통합
- **기개발 Agent (Producer):** 문의·장애·모니터링 이력 활용
- **4-4 성과측정 체계:** 보고 산출물이 성과 근거 데이터로도 재활용

### 영역 전체 목표수준: **55~70%**

## B-1. 운영 개선 Agent

**대응 업무 영역:** 업무지원 (RFP 3.4 비중 2%)

**Agent 역할:** 장애·문의·변경 이력을 패턴 분석하여 개선 과제를 능동적으로 발굴하고, 운영 환경 관련 지원 업무를 자동화한다. 사후 대응에서 선제 개선으로의 패러다임 전환을 지향한다.

### 세부 액티비티 분해

|세부 액티비티|As-Is|To-Be|실행방안|목표수준|
|---|---|---|---|:-:|
|개선 과제 발굴|운영자 경험 기반 수시 제기|Agent 패턴 분석 기반 자동 발굴|장애·문의 이력의 유사성·빈도·영향도 분석. 개선 후보 리스트 자동 생성.|**40~60%**|
|반복 이슈 근본원인 분석|이슈별 개별 분석|Agent 이력 통합 분석 + 원인 후보 제시|유사 이슈 클러스터링. 근본원인 추론 결과를 운영자에 제시.|**30~50%**|
|운영 환경 구축 가이드|수작업 매뉴얼 참조|Agent 자동 가이드 생성·업데이트|환경 구성 정보 기반 가이드 자동 생성·버전 관리.|**50~70%**|
|신기능 검토|수작업 영향도 평가|Agent 이력 기반 영향도 초안 제공|과거 변경 이력과 비교하여 예상 리스크·영향 범위 도출.|**30~50%**|

### Agent 내부 구성

- **패턴 분석 모듈:** 이력 데이터 클러스터링·빈도 분석
- **원인 추론 모듈:** 유사 이력 기반 근본원인 후보 생성
- **가이드 생성 모듈:** 환경·절차 가이드 자동 작성
- **영향도 분석 모듈:** 변경 이력 기반 리스크 평가

### Agent 간 연계

- **기개발 Agent (Producer):** 이상상황 조치가이드·문의대응 Agent의 처리 이력이 핵심 입력
- **B-2 운영 지식 Agent:** 발굴된 개선 과제·원인 분석 결과가 교육·지식 자산으로 재활용
- **A-2 운영 리포트 Agent:** 개선 과제가 정기 보고 항목으로 통합
- **4-2 Orchestration:** 반복 이슈 감지 시 관련 Agent 자동 호출

### 영역 전체 목표수준: **35~55%**

## B-2. 운영 지식 Agent

**대응 업무 영역:** 교육 (RFP 3.4 비중 1%)

**Agent 역할:** 시스템 변경 이력·운영 매뉴얼·개발 산출물을 기반으로 교육·온보딩 자원을 자동 생성·제공하여, 지식 전달 체계의 시간·품질 편차를 제거한다.

### 세부 액티비티 분해

|세부 액티비티|As-Is|To-Be|실행방안|목표수준|
|---|---|---|---|:-:|
|신규 운영자 온보딩|선임 운영자 수작업 교육|Agent 자연어 Q&A + 학습 경로 제공|시스템별 운영 매뉴얼·릴리즈 노트 통합 지식베이스. 자연어 질의 응답.|**40~60%**|
|시스템 변경 교육 자료|변경마다 수작업 작성|변경 이력 기반 Agent 드래프트 생성|릴리즈 노트·변경 이력 기반 교육 자료 자동 생성. 운영자 검수 후 배포.|**50~70%**|
|교육 이수 관리|수작업 체크리스트|Agent 자동 트래킹·알림|학습 이수 현황·미이수 항목 자동 관리·알림.|**60~80%**|
|의무 교육 관리|수작업 안내·집계|Agent 자동 안내·이수 집계|의무 교육 일정·대상·이수 여부 자동 관리.|**60~80%**|

### Agent 내부 구성

- **지식베이스 관리 모듈:** 매뉴얼·릴리즈 노트·산출물 통합·버전 관리
- **Q&A 엔진:** 자연어 질의 기반 답변 생성
- **자료 생성 모듈:** 변경 이력 기반 교육 자료 드래프트
- **이수 관리 모듈:** 교육 현황·알림·집계

### Agent 간 연계

- **기개발 Agent (Producer):** 분석/설계·코딩 Agent의 산출물(PRD·코드가이드 등)이 교육 자료 원천으로 활용
- **B-1 운영 개선 Agent:** 개선 과제·근본원인 분석 결과가 교육 사례로 축적
- **4-2 Orchestration:** 신규 운영자 온보딩 프로세스 전반을 Agent 조합으로 제공

### 영역 전체 목표수준: **50~70%**

## 신규 4개 Agent 통합 요약

### 영역별 목표수준 및 가중 기여도

|Agent|대응 영역|비중|영역 목표수준|**가중 기여도**|
|---|---|:-:|:-:|:-:|
|A-1 SLA 관리|서비스 수준 관리|3%|65~80%|**2.0~2.4%**|
|A-2 운영 리포트|업무회의/보고|6%|55~70%|**3.3~4.2%**|
|B-1 운영 개선|업무지원|2%|35~55%|**0.7~1.1%**|
|B-2 운영 지식|교육|1%|50~70%|**0.5~0.7%**|
|**합계**||**12%**||**6.5~8.4%**|

→ 신규 Agent 4종은 전체 ITO 업무량 중 **6.5~8.4%의 자동화 효과**를 기여한다 (회의록 10-2의 "비중 × 목표수준" 평가식 기준 단일 점수 환산).

### 공통 설계 원칙 재확인

- **Minimize:** 2개의 공통 데이터축(운영 실적·운영 지식) 공유로 데이터 파이프라인 중복 배제
- **Connect:** 기개발 Agent를 Producer로, 신규 Agent를 Consumer로 연계. 신규 Agent 간에도 A-1↔A-2, B-1↔B-2 연계
- **Measure:** 모든 Agent의 출력이 4-4 성과측정 체계로 직접 연결

### 단계적 고도화 로드맵

- **1단계 (확보 가능 데이터 기반):** Agent 실행 이력, 모니터링 툴, 운영 문서를 입력으로 활용
- **2단계 (ITSM 환경 확보 후):** 로 데이터 기반 정밀 측정·예측으로 확장
