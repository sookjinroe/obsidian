# 요약본 2단계: 한 문단 요약 (임원 브리핑용)

> 본 과제에서는 운영 영역의 비중 12% 구간(서비스 수준 관리 3%, 업무회의/보고 6%, 업무지원 2%, 교육 1%)에 신규 Agent 4종을 투입한다. 각 Agent는 **운영 실적 데이터축**과 **운영 지식 데이터축** 이라는 두 개의 공통 데이터 레이어 위에서 작동하며, 기개발 Agent를 데이터 Producer로 재정의하여 중복 파이프라인 없이 확장 가능한 구조를 구축한다. 영역별 목표수준은 35~80% 범위이며, 가중 기여도 합산 시 전체 ITO 업무량의 **6.5~8.4% 자동화 효과**를 확보한다.

# 요약본 3단계: 한 페이지 요약 (제안팀 공유용)

## 신규 운영 Agent 4종 개요

### 설계 원칙

- **2개 공통 데이터축** 위에 Agent 구축 (운영 실적·운영 지식)
- **기개발 Agent를 Producer로 재정의** — 단순 고도화 넘어선 구조적 재배치
- **단계적 데이터 수집** — 1단계(확보 가능 소스) → 2단계(ITSM 환경 확보 후)

### Agent 구성

|Agent|대응 영역|비중|목표수준|핵심 기능|
|---|---|:-:|:-:|---|
|**A-1 SLA 관리**|서비스 수준 관리|3%|65~80%|SLA 자동 집계, 미달 리스크 예측, 원인 분석|
|**A-2 운영 리포트**|업무회의/보고|6%|55~70%|보고서 드래프트 자동 생성, 회의록 요약, 액션 아이템 추적|
|**B-1 운영 개선**|업무지원|2%|35~55%|패턴 분석 기반 개선 과제 발굴, 환경 가이드 자동 생성|
|**B-2 운영 지식**|교육|1%|50~70%|자연어 Q&A, 교육 자료 자동 생성, 이수 관리|

### 가중 기여도

- 신규 Agent 4종 합산: **전체 ITO 업무량 중 6.5~8.4% 자동화 효과**

### 3대 축 매핑

- **Minimize:** 데이터 파이프라인 공유로 중복 배제
- **Connect:** 기개발 Agent(Producer) ↔ 신규 Agent(Consumer), 신규 간 연계
- **Measure:** 모든 Agent 출력이 4-4 성과측정 체계로 직결

### 다음 섹션과의 연결

- 4-1-(가) 기개발 고도화: Producer 역할 재정의로 연결
- 4-2 Orchestration: Agent 간 호출 구조 설계
- 4-4 성과측정: 신규 Agent 출력이 핵심 입력 데이터

# 요약본 4단계: 핵심 메시지 3개 (프레젠테이션 슬라이드용)

### 슬라이드 1: 무엇을 만드는가

> **운영 영역 4개 업무에 신규 Agent 4종**
> 
> - SLA 관리 · 운영 리포트 · 운영 개선 · 운영 지식

### 슬라이드 2: 어떻게 설계하는가

> **개별 Agent가 아닌, 공통 데이터축 위의 Agent 생태계**
> 
> - 운영 실적 데이터축: A-1 / A-2가 공유
> - 운영 지식 데이터축: B-1 / B-2가 공유
> - 기개발 Agent는 데이터 Producer로 재정의

### 슬라이드 3: 얼마나 효과적인가

> **전체 ITO 업무량의 6.5~8.4% 자동화 (영역 가중 기여도 기준)**
> 
> - 영역별 목표수준: 35~80%
> - 단계적 확장: ITSM 환경 확보 시 효과 증폭
