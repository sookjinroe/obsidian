
## 1-1. 설계 접근

본 과제의 신규 운영 Agent는 **입출력 데이터를 공유하는 업무들을 하나의 Agent로 묶어** 중복 파이프라인을 제거하고 일관성을 확보한다. 그 결과 3종 Agent는 **2개의 공통 데이터축**(운영 실적·운영 지식)을 공유하는 구조로 구성되며, Agent 간 연계는 데이터 인터페이스 수준에서 표준화된다.

RFP 비중표의 업무 영역에 1:1로 매핑하지 않고, 각 Agent의 기능이 결과적으로 커버하는 **사후 매핑**으로 표현한다.

## 1-2. 전체 구조 다이어그램

**다이어그램 의도:** 2개 데이터축 위에 3개 Agent가 올라간 구조. 데이터축이 하단 기반, Agent가 상단에 배치. Agent 간 연계 화살표가 수평으로 흐름.

```
                 ┌──────────────────────────────────────────────────┐
                 │                3종 신규 운영 Agent                │
                 │                                                  │
                 │  ┌──────────┐   ┌──────────┐   ┌──────────┐   │
                 │  │  운영     │◀─▶│  운영     │   │  운영    │   │
                 │  │ 인사이트  │   │ 개선      │◀─▶│ 지식     │   │
                 │  │          │   │          │   │          │   │
                 │  └────┬─────┘   └────┬─────┘   └────┬─────┘   │
                 └───────┼──────────────┼──────────────┼──────────┘
                         │              │              │
              ┌──────────┴──────────┐  │  ┌───────────┴──────────┐
              │  데이터축 1          │  │  │  데이터축 2           │
              │  운영 실적 데이터    │◀─┘  │  운영 지식 데이터      │
              │                      │     │                       │
              │  기본: 티켓·모니터링 │     │  기본: 매뉴얼·릴리즈   │
              │  강화: 문의대응      │     │  강화: 이상상황         │
              │       Agent 고도화   │     │       조치가이드 고도화 │
              └──────────────────────┘     └───────────────────────┘
```

## 1-3. 공통 데이터축

|**구분**|**데이터축 1. 운영 실적 데이터**|**데이터축 2. 운영 지식 데이터**|
|---|---|---|
|**성격**|**정량적 이력 데이터**<br>("무엇이 언제 얼마나 처리되었나")|**정성·구조화 지식**<br>("무엇이 왜 발생했고 어떻게 해결되는가")|
|**원천 소스<br>(기본)**|• **티켓 시스템**: 문의·요청·장애 접수 및 처리 이력<br>• **모니터링 툴**: 알람·이벤트·성능 지표<br>• **계약 문서**: SLA 정의 및 기준|• **문서류**: 장애 대응 매뉴얼, 운영 가이드, 릴리즈 노트<br>• **이력**: 과거 장애 이력 (원인·조치·결과 구조화)|
|**원천 소스<br>(강화)**|• **문의대응 Agent 고도화 산출물**: 카테고리 태깅, SLA 메타데이터, 해결방식 분류 등 구조화된 처리 메타|• **이상상황 조치가이드 Agent 고도화 산출물**: 증상-원인-조치-교훈 구조로 축적된 대응 사례|
|**가공 레이어**|• 특정 솔루션에 비종속적인 **소스별 어댑터** 활용<br>• 표준 스키마 기반의 **정제 및 통합**<br>• Agent 내부가 아닌 **플랫폼 수준의 공통 가공 레이어**로 분리|• **문서 임베딩 및 인덱싱**<br>• **대응 사례 구조화** (증상-원인-조치-교훈)<br>• **메타데이터 부여** (난이도·빈도·재사용성)|
|**주 소비 Agent**|운영 인사이트, 운영 개선|운영 지식, 운영 개선|

> **기본 소스:** 과제 착수 시점부터 확보 가능. 신규 Agent 기본 동작이 가능한 수준. **강화 소스:** 기개발 Agent 고도화 완료 시점부터 추가됨. 신규 Agent의 분석 정밀도·가이드 품질이 향상됨.

## 1-4. Agent 3종 개요

|Agent|핵심 역할|주 데이터축|RFP 대응 비중|
|---|---|---|:-:|

# 페이지 2. 운영 인사이트 Agent

## 2-1. 역할 정의

운영 실적 데이터를 기반으로 SLA 측정, 운영 현황 분석, 보고 산출물 생성을 수행한다. 단일 데이터 원천 위에서 **대시보드·리포트·대화형 분석**이라는 세 가지 사용 방식을 통합 제공한다.

## 2-2. RFP 대응 영역 및 목표수준

| RFP 영역    |   비중   | 담당 범위                |
| --------- | :----: | -------------------- |
| 서비스 수준 관리 |   3%   | SLA 측정·분석·보고         |
| 업무회의/보고   |   6%   | 정기·비정기 보고서 생성, 회의 지원 |
| **합계**    | **9%** |                      |

**목표수준 (레인지):**

- 기본 기능 (집계·측정·알림): **80~90%**
- 협업 기능 (분석·보고서 초안): **50~70% 품질 초안**

**파일럿 범위:** 핵심 2~3개 시스템, 주요 SLA 메트릭 2~3개 (가용성·응답시간 등)로 시작 → 어댑터 확장으로 시스템·메트릭 추가

## 2-3. Agent 구조

**다이어그램 의도:** 좌측 입력 → 중앙 처리(3개 기능 블록) → 우측 출력. 각 기능 블록의 출력이 서로 피드백되는 관계(SLA 집계 결과 → 분석 입력, 분석 결과 → 보고서 입력)도 표시.

```
[입력]                        [처리 기능]                        [출력]
─────────                     ──────────────                     ─────────

티켓 처리 이력 ──┐
                  │
모니터링 지표  ──┼─────▶  [SLA 집계·측정]    ─────────▶    실시간 대시보드
                  │                │                              임계치 이탈 알림
SLA 정의서    ──┘                 │ 집계 결과
                                    ▼
누적 실적 데이터 ───────▶  [추세·원인 분석]   ─────────▶    분석 리포트
                                    │                              대화형 답변
                                    │ 분석 결과
                                    ▼
보고 템플릿    ──┐                │
                  ├────▶  [보고서·회의 지원] ─────────▶    정기·임시 보고서
회의 컨텍스트 ──┘                                          회의록 요약·액션
```

## 2-4. 제공 기능

### 기능 1. SLA 집계·측정 (자동화 수준: 높음)

운영 실적 데이터를 기반으로 SLA 달성 현황을 실시간으로 측정·시각화하고, 미달 위험을 사전 알림한다.

- **입력:** 티켓 처리 이력, 모니터링 지표, SLA 정의서
- **처리:** 계약 기준 기반 실시간 집계, 임계치 감지, 추세 예측
- **출력:** SLA 대시보드(실시간 달성률·추세), 미달 임박 알림(메신저·이메일)

### 기능 2. 추세·원인 분석 (자동화 수준: 중간)

SLA 추세 변화와 미달 원인을 분석하고, 자연어 기반 탐색적 질의를 지원한다. 담당자의 원인 규명·개선 판단을 지원하는 정보를 제공한다.

- **입력:** 누적 운영 실적 데이터, 담당자 자연어 질의
- **처리:** 시계열 추세 분석, 관련 로그·티켓 상관분석, 대화형 응답 생성
- **출력:** 분석 리포트(추세·이상 구간·원인 후보), 대화형 답변(근거 데이터 포함)

### 기능 3. 보고서·회의 지원 (자동화 수준: 중간)

정기·비정기 운영 보고서를 자동 생성한다. 데이터 집계뿐 아니라 추세 해석과 개선 제언까지 포함한 초안을 제공하여 담당자가 검수·확정 업무에 집중할 수 있도록 지원한다. 회의록 요약·액션 아이템 추출도 포함한다.

- **입력:** 운영 실적 데이터(기능 1·2 출력 포함), 보고 템플릿, 회의 컨텍스트(음성·채팅·문서)
- **처리:** 회의체별 포맷 기반 드래프트 생성(데이터+해석+제언), 회의록 자동 요약·구조화
- **출력:** 주간·월간 보고서, 임시 리포트, 회의록 요약, 액션 아이템 트래킹

## 2-5. 사용 방식

|모드|상호작용|사용 상황|
|---|---|---|
|상시 모니터링|Push (대시보드·알림)|SLA 현황 수시 확인, 미달 임박 감지|
|정기·임시 보고|Pull (버튼 또는 자연어 트리거)|보고 시점에 문서 자동 생성|
|탐색적 분석|Conversational (자연어 대화)|"왜 이번 주 SLA가 떨어졌지?" 같은 심층 탐색|

# 페이지 3. 운영 지식 Agent

## 3-1. 역할 정의

운영 지식(매뉴얼·장애 대응 이력·릴리즈 노트)을 축적·구조화하여, **실시간 장애 대응 가이드**와 **신규 운영자 온보딩·학습**을 동시에 지원한다. 사용자 맥락에 따라 응답 방식을 분기하는 구조로 설계된다.

**기개발 Agent와의 관계:** 기개발 이상상황 조치가이드 Agent와 통합 설계된다. 본 과제에서 기개발 Agent의 고도화는 단순 성능 향상이 아니라 **운영 지식 Agent로의 발전**을 의미한다. 하나의 지식 베이스를 공유하여 중복 제거, 대응·학습의 경계가 사라진 Adaptive Agent로 구현.

## 3-2. RFP 대응 영역 및 목표수준

|RFP 영역|비중|담당 범위|
|---|:-:|---|
|이상상황 조치가이드|2%|실시간 장애 대응 가이드 (기개발 고도화 포함)|
|교육|1%|온보딩·학습·의무교육 관리|
|**합계**|**3%**||

**목표수준 (레인지):**

- 기본 기능 (검색·Q&A·이수관리): **80~90%**
- 협업 기능 (가이드·교육자료 초안): **60~80% 품질 초안**

## 3-3. Agent 구조

**다이어그램 의도:** 좌측 지식 베이스(통합 저장소) → 중앙 처리(3개 기능 블록) → 우측 출력. 사용자 컨텍스트에 따라 응답 모드가 분기됨을 표시.

```
[지식 베이스]                  [처리 기능]                      [출력]
─────────                      ──────────────                   ─────────

운영 매뉴얼 ──┐
              │
릴리즈 노트 ──┤
              ├──▶  [매뉴얼·사례 Q&A]   ───────────▶  응답 + 근거 문서
장애 대응   ──┤            │
이력        ──┤            │ 조회
              │            ▼
근본원인    ──┤     [장애 대응 가이드]   ───────────▶  체크리스트
분석        ──┘            │                              조치 제안
                           │
                           │ 지식 확장
                           ▼
사용자      ────────▶ [학습·온보딩 지원] ───────────▶  학습 응답 (학습 모드)
컨텍스트                                                  교육 자료
                                                          이수 현황 알림
```

## 3-4. 제공 기능

### 기능 1. 매뉴얼·사례 Q&A (자동화 수준: 높음)

운영 매뉴얼·릴리즈 노트·과거 장애 사례를 통합 지식 베이스로 관리하며, 자연어 질의 기반 응답을 제공한다.

- **입력:** 자연어 질의, 사용자 컨텍스트(역할·현재 작업)
- **처리:** 의미 기반 검색, 관련도 랭킹, 자연어 응답 생성, 근거 문서 링크
- **출력:** 질의 응답, 관련 매뉴얼·사례 링크 목록

### 기능 2. 장애 대응 가이드 (자동화 수준: 중간)

장애 발생 시 현재 상황과 과거 유사 사례를 비교하여 대응 가이드를 제시한다. 운영자가 최종 판단·실행.

- **입력:** 현재 장애 상황(증상·시스템·시각), 과거 유사 사례, 대응 매뉴얼
- **처리:** 유사도 분석, 상황별 체크리스트 구성, 조치 순서 추천
- **출력:** 대응 체크리스트, 조치 제안, 관련 사례 레퍼런스

### 기능 3. 학습·온보딩 지원 (자동화 수준: 중간)

신규 운영자 온보딩, 시스템 변경 교육, 의무 교육 관리를 통합 지원한다. 사용자 수준·역할에 따라 맞춤 학습 경로를 제공한다.

- **입력:** 사용자 프로필(역할·경력), 교육 이수 이력, 변경 이력·릴리즈 노트
- **처리:** 맞춤 학습 경로 생성, 변경 이력 기반 교육 자료 드래프트, 이수 현황 트래킹
- **출력:** 학습 모드 Q&A 응답(맥락 설명 포함), 교육 자료 드래프트, 이수 알림

## 3-5. 사용 방식 — 모드 분기

동일 지식 베이스를 사용하되, 사용자 컨텍스트에 따라 응답 방식이 전환된다.

|모드|응답 방식|대상 상황|
|---|---|---|
|**숙련자 모드**|간결한 체크리스트, 핵심 조치만|실시간 장애 대응 중|
|**학습자 모드**|맥락 설명 포함 상세 응답, 관련 개념 확장|온보딩·학습|
|**검색 모드**|매뉴얼·사례·릴리즈 노트 통합 검색 결과|정보 탐색|

사용자 컨텍스트(역할·현재 작업·긴급도) 기반으로 모드 자동 전환, 사용자가 수동 선택도 가능.

# 페이지 4. 운영 개선 Agent

## 4-1. 역할 정의

장애·문의·변경 이력을 분석하여 반복 패턴과 근본원인을 도출하고 **개선 과제를 능동적으로 발굴**한다. 운영 환경 구축·유지 가이드 생성과 변경 영향도 분석을 포함한다. 사후 대응에서 **선제적 개선**으로의 패러다임 전환을 지향한다.

**전체 시스템에서의 위치:** RFP 직접 대응 비중은 작으나, 본 Agent의 출력이 **운영 인사이트 Agent**(보고서의 개선 섹션)와 **운영 지식 Agent**(교육 사례·대응 가이드 축적)의 입력으로 순환되므로, 시스템 전반의 가치 기여도는 비중 이상이다.

## 4-2. RFP 대응 영역 및 목표수준

|RFP 영역|비중|담당 범위|
|---|:-:|---|
|업무지원|2%|개선 발굴, 환경 구축 가이드, 신기능 검토|
|**합계**|**2%**||

**목표수준 (레인지):**

- 기본 기능 (패턴 분석·가이드 생성): **70~85%**
- 협업 기능 (개선 과제·원인 분석 초안): **40~60% 품질 초안**

> 협업 기능 목표수준이 상대적으로 낮은 이유: 개선 과제 발굴은 사업 맥락·조직 역학 반영이 필요한 난이도 높은 지능 업무로, Agent가 완성도 높은 결과를 내기 어려움. 담당자 판단과의 협업이 전제.

## 4-3. Agent 구조

**다이어그램 의도:** 좌측 이력 데이터(두 데이터축 모두 활용) → 중앙 처리(3개 기능 블록) → 우측 출력. 출력이 다른 Agent(인사이트·지식)로 피드백되는 화살표도 표시.

```
[입력 — 두 데이터축 모두 활용]      [처리 기능]                  [출력]
─────────────                       ──────────────                 ─────────

티켓 처리 이력 ──┐
                  │
장애 대응 이력 ──┼──▶  [반복 패턴 분석]   ─────────▶  패턴 리포트
                  │            │                              이상치 알림
시스템 변경    ──┘            │ 패턴 결과
이력                           ▼
                        [개선 과제 발굴]   ─────────▶  개선 과제 리스트
                               │                              근본원인 분석
환경 구성 정보 ──┐            │ 분석 결과                    → 운영 인사이트·
                  │            ▼                                운영 지식으로 연계
신기능 요구사항 ┘     [환경·영향도 가이드] ─────────▶  환경 구축 가이드
                                                              영향도 리포트
```

## 4-4. 제공 기능

### 기능 1. 반복 패턴 분석 (자동화 수준: 높음)

장애·문의·변경 이력을 분석하여 반복 발생 패턴과 이상치를 자동으로 탐지한다.

- **입력:** 티켓 처리 이력, 장애 대응 이력, 시스템 변경 이력
- **처리:** 유사성·빈도 기반 클러스터링, 시간대·시스템별 패턴 추출, 통계적 이상치 감지
- **출력:** 패턴 리포트(빈도·영향도·추세), 이상치 자동 알림

### 기능 2. 개선 과제 발굴 (자동화 수준: 중간)

패턴 분석 결과를 바탕으로 근본원인을 추론하고 개선 과제 후보를 도출한다. 담당자의 우선순위 판단·실행 결정을 지원.

- **입력:** 기능 1의 패턴 분석 결과, 과거 개선 이력, 시스템 변경 이력
- **처리:** 유사 이슈 클러스터링 기반 근본원인 추론, 개선 후보 자동 생성, 예상 효과 추정
- **출력:** 개선 과제 리스트(제목·배경·제안·영향도), 근본원인 분석 리포트

→ 출력은 **운영 인사이트 Agent**(보고서의 개선 섹션)와 **운영 지식 Agent**(교육 사례 축적)로 연계됨.

### 기능 3. 환경·영향도 가이드 (자동화 수준: 중간)

운영 환경 구축·유지를 위한 가이드를 자동 생성하고, 변경 요청에 대한 영향도 분석 초안을 제공한다.

- **입력:** 환경 구성 정보, 변경 이력, 신기능 요구사항
- **처리:** 환경 구성 기반 가이드 자동 작성·버전 관리, 과거 변경 이력 비교 기반 영향 범위 도출
- **출력:** 환경 구축 가이드(절차·체크리스트), 변경 영향도 리포트(예상 영향·리스크)

## 4-5. 사용 방식

|모드|상호작용|사용 상황|
|---|---|---|
|정기 리포트|Push|주기적 패턴 분석 결과 자동 공유|
|On-demand 분석|Pull|특정 이슈·영역에 대한 분석 요청|
|대화형 탐색|Conversational|"왜 최근 이 시스템 장애가 늘었지?" 류 질의|

## 부록. 기개발 Agent 고도화 요구사항 (역산)

본 신규 Agent가 정상 동작하려면 기개발 Agent가 다음 기능을 갖춰야 한다. 이는 4-1-(가) 기개발 고도화의 구체 스펙이 된다.

### 문의대응 Agent 고도화 스펙

운영 인사이트·운영 개선 Agent가 요구하는 기능:

- 티켓 단위 구조화 이력 저장 (타임스탬프·분류·상태 전이·SLA 메타)
- 해결방식 구조화 기록 (조치 내용 분류·참조 매뉴얼)
- 표준 스키마 준수 (다른 Agent의 정형 쿼리 가능)

### 이상상황 조치가이드 Agent 고도화 스펙

**운영 지식 Agent로의 발전**을 전제로 한 고도화:

- 장애 대응 이력의 구조화 저장 (원인·조치·결과·재발 여부)
- 교육 가능한 사례 서술 (증상-원인-조치-교훈 구조)
- 메타데이터 부여 (난이도·빈도·재사용성)
- 사용자 모드별 응답 분기 기능 (숙련자 vs 학습자)

### 기타 기개발 Agent

시스템 모니터링·화면작동 모니터링·데이터 추출 Agent는 **자체 성능 향상** 관점에서 고도화하되, 신규 Agent의 필수 입력 소스로 위치시키지 않는다. 원천 데이터는 모니터링 툴·티켓 시스템 등 외부 소스에서 직접 수집 가능.
