## 1장. 전체 아키텍처
#### 장 개요
전체 아키텍처는 메인/공통 영역과 프로젝트 제안룸의 이중 구조로 구성하여, 제안 자료의 체계적 관리·재활용, 제안 과정 협업·운영, 조직 내 지식공유 활성화를 통합 지원한다.

#### 1.1 시스템 영역 구조
- 자산 재활용성과 진행 중 보안성을 동시에 확보하기 위해 두 영역으로 분리 설계
    - 이중 영역 구조의 필요성 (재활용성 vs 보안)
    - 메인/공통 영역의 역할 (사용 현황, 표준 목차, 템플릿, 우수 제안서, 통합검색)
    - 프로젝트 제안룸의 역할 (구성원 관리, 산출물 등록·관리, 진도관리, 최종 확정)
    - 영역별 사용자·기능·라이프사이클 비교
- **RFP 매핑**: 1)-3, 3)-1, 3)-2, 3)-3

#### 1.2 영역 연계 구조
- 프로젝트 산출물이 공통 자산으로 이어지는 데이터 흐름과 통합 검색 기반 지식공유 채널을 정의, 향후 확장 가능한 구조로 설계
    - 영역 간 자산 흐름 (자산화 흐름 + 자산 활용 흐름, 3장 연계)
    - 통합 검색 기반 지식공유 (포털 통합검색 + 제안룸 검색 이중화, 5장 연계)
    - 향후 확장성 (영역 추가, 외부 시스템 연계 여지)
- **RFP 매핑**: 1)-1, 1)-2, 1)-3 (확장성), 1)-5


## 2장. 권한·보안 체계
### 장 개요
권한·보안 체계는 포털 시스템과 통합된 권한 모델을 기반으로 사용자 유형별 차등 접근통제와 행위 이력관리를 일관되게 제공한다.

### 2.1 통합 권한체계
- 포털 시스템과 단일 사용자/역할 모델을 공유하여 권한 관리 일관성을 확보, 향후 타 시스템 확장 가능한 표준 모델로 설계
    - 포털 시스템 연계 (SSO + 권한 동기화)
    - 사용자 유형 정의: 일반사용자 / 제안룸 사용자(임직원) / 협력사 / 운영자
    - Role 기반 권한 모델 + 권한 매트릭스
    - 확장 청사진: 제안룸을 시작점으로 한 권한 통합관리 표준화
- **RFP 매핑**: 1)-4, 2)-1, 2)-2

### 2.2 접근통제 및 이력관리
- 영역·사용자 유형 기준 차등 접근통제와 주요 행위 이력 기록을 통합 운영하여 사업수주 및 지적재산 보호 요건 충족
    - **[A. 접근통제 정책]** 영역별 접근통제 / 사용자 유형별 접근·다운로드 제한 / 검색 결과 차등 (5장 연계)
    - **[B. 행위 이력관리]** 이력 관리 대상 행위 / 로그 항목 표준 / 보안 감사 및 운영 관리(6장) 활용
- **RFP 매핑**: 2)-3, 4)-1, 4)-2, 4)-3


## 3장. 공통 자산 관리

### 장 개요
**제안 산출물의 등록·관리·갱신 통합 체계 구축**
공통 자산 관리는 산출물을 분류·등록·갱신하는 체계를 구축하여 RFP 5번(공통 자산 관리)과 9번(메타데이터 관리)의 요구를 통합 대응한다.

### 3.1 공통 자산 구성 체계
- 자산을 활용 목적별로 4유형으로 분류하여 등록·검색·갱신 단계에서 차등화된 관리 기준 적용
    - 자산 4유형 정의: 표준 제안 목차 / 제안 템플릿 / 우수 제안서 / 최종 산출물
    - 유형별 정의·활용 시점·관리 특성
    - 자산 간 관계 (양식화 / 자산화 검토 / 평가·선정 흐름)
- **RFP 매핑**: 5)-1, 5)-2

### 3.2 자산화 워크플로우 및 메타데이터 관리체계
- 표준 등록 프로세스와 메타데이터 체계로 자산 등록의 일관성과 검색 가능성 확보
    - 자산화 4단계: 프로젝트 종료 → 자산화 검토 → 메타데이터 부여 → 공통 영역 등록
    - 단계별 책임자, 자산화 시점(자동 후보 등록 + 수동 신청), 등록 시 검증 포인트
    - 메타데이터 스키마: 분류 메타데이터(사업유형·규모·특성) + 시스템 메타데이터
    - 메타데이터 운영 모델: 입력 표준 가이드 / 등록 시 검증 룰 / 정합성 점검
- **RFP 매핑**: 5)-1, 9)-1, 9)-2

### 3.3 자산 변경 및 품질 관리
- 변경이력 추적과 갱신 사이클 운영으로 자산 신뢰성과 활용 가치 유지
	- 변경이력 관리: 자산 단위(등록·수정·삭제 / 작업자 / 시점 / 사유) + 항목 단위(메타데이터·첨부·권한)
    - 버전 관리 정책: 주요 변경 시 버전 갱신, 이전 버전 조회
    - 우수 제안서 선정·갱신: 선정 기준(운영 정책) + 정기·비정기 갱신
    - 표준 제안 목차 개선: 현장 사용 데이터 기반 주기적 갱신
- **RFP 매핑**: 5)-2, 5)-3

## 4장. 프로젝트 제안룸

프로젝트 제안룸은 프로젝트 단위 제안서 작성·협업·확정을 위한 작업 공간이다. 제안 과정의 계획·실행·산출물 관리 흐름에 따라 3단계로 기능을 구성한다.

#### 4.1 제안 계획
- 구성원 등록, 표준 목차 적용·변형, 담당자 배정·일정 수립으로 제안 작성 기반 마련
    - 제안룸 생성 및 구성원 등록·역할 부여
    - 표준 목차 적용 → 프로젝트별 수정·삭제·추가 (3장 연계)
    - 목차 항목별 작업담당자 지정
    - 제안 일정 수립 (전체 마감일, 항목별 마감일)
- **RFP 매핑**: 6)-1, 6)-2

#### 4.2 제안 실행
- 목차 항목별 산출물 등록·관리와 작성 현황·기간 기반 진도관리로 제안 작성 운영
    - 목차 항목별 산출물 등록·수정·버전 관리
    - 진도 관리: 전체 / 항목별 / 담당자별
    - 협업 지원: 담당자 변경, 알림 등
- **RFP 매핑**: 6)-3, 6)-4

#### 4.3 산출물 확정
- 최종 산출물 확정 처리와 변경이력 관리로 산출물 신뢰성 확보, 자산화 후보로 연결 (3장 연계)
    - 최종 산출물 확정 처리 (확정 권한자 지정 + 확정)
    - 변경이력 관리 (산출물 단위 / 항목 단위)
    - 자산화 후보 등록 (3장 자산화 워크플로우 연계)
- **RFP 매핑**: 6)-5

## 5장. 검색 체계
#### 장 개요
검색 체계는 통합검색과 제안룸 내 검색을 분리한 이중 채널 구조로 구성하고, 권한과 메타데이터를 기반으로 사용자별 검색 결과를 차등 제공한다.

#### 5.1 검색 이중화 구조
- 자산 발견과 작업 회수의 목적이 다른 두 검색을 분리하여 각 목적에 맞는 결과 제공
- **담을 내용**:
    - 두 검색의 목적·범위 정의 (통합검색 = 발견 / 제안룸 내 검색 = 회수)
    - 포털 통합검색: 자산화된 제안 자료를 포털에서 검색 (3장 자산화 결과 활용)
    - 제안룸 내 검색: 진행 중 프로젝트 내부 검색
- **RFP 매핑**: 1)-5, 7)-1

#### 5.2 권한·메타데이터 기반 결과 차등

- **헤드라인**: 권한과 메타데이터 기반 검색 결과 차등 노출
- **핵심**: 사용자 권한과 메타데이터를 기반으로 검색 결과를 차등 제공하여 보안과 검색 정확도 동시 확보
- **담을 내용**:
    - 권한 기반 결과 필터링 (2장 권한체계 연계)
    - 메타데이터 기반 검색 필터 (3장 스키마 활용)
- **RFP 매핑**: 2)-3, 7)-2
