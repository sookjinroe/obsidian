# 1장. 전체 아키텍처
## 요약 버전

### 장 도입

**이중 영역 아키텍처 기반의 제안 자료 관리·협업·지식공유 통합 구조**

전체 아키텍처는 메인/공통 영역과 프로젝트 제안룸의 이중 구조로 구성하여, 제안 자료의 체계적 관리·재활용, 제안 과정 전반의 협업과 운영, 조직 내 지식공유 활성화를 통합 지원한다. RFP 1)(전체 구축 방향)과 3)(제안룸 구조 설계) 요구사항을 통합 대응하기 위해 2가지 축으로 구성한다.

|Sub-section|다루는 내용|RFP 매핑|
|---|---|---|
|1.1 시스템 영역 구조|메인/공통 영역과 프로젝트 제안룸의 분리 설계|1)-3, 3)-1, 3)-2, 3)-3|
|1.2 영역 연계 구조|영역 간 데이터 흐름 + 지식공유 활성화 + 확장성|1)-1, 1)-2, 1)-3, 1)-5|

---

### 1.1 시스템 영역 구조

**헤드라인 메시지** 메인/공통 영역과 프로젝트 제안룸의 이중 영역 구조

**핵심 메시지** 자산 재활용성과 진행 중 보안성을 동시에 확보하기 위해 시스템을 메인/공통 영역과 프로젝트 제안룸으로 분리하여 설계한다.

#### 가. 이중 영역 구조의 필요성

제안 자료는 두 가지 요건을 동시에 충족해야 한다. 자산 재활용을 위해서는 자료가 폭넓게 공유되어야 하지만, 진행 중인 제안 자료는 보안 통제가 필요하다. 단일 영역으로는 두 요건을 동시에 충족하기 어려우므로 영역을 분리한다.

#### 나. 메인/공통 영역

- **역할**: 자산 재활용을 위한 통합 관리 영역
- **주요 기능**: 제안룸 사용 현황, 표준 제안 목차, 제안 템플릿, 우수 제안서, 통합검색
- **사용자**: 권한 부여된 임직원 전반

#### 다. 프로젝트 제안룸

- **역할**: 프로젝트 단위 협업·산출물 관리 영역
- **주요 기능**: 구성원 관리, 표준 목차 기반 제안서 구성, 산출물 등록·관리, 진도관리, 최종 산출물 확정
- **사용자**: 등록된 임직원 + 협력사 (제한적)

#### 라. 영역별 비교

|구분|메인/공통 영역|프로젝트 제안룸|
|---|---|---|
|목적|자산 재활용|프로젝트 협업·관리|
|접근 사용자|임직원 전반 (권한별 차등)|등록 구성원 + 협력사|
|자산 라이프사이클|등록·조회·갱신 (장기)|작업·확정 (프로젝트 기간)|
|보안 특성|자산 단위 권한 관리|영역 단위 격리|

**RFP 매핑**: 1)-3 (영역 분리), 3)-1 (영역 구분 설계), 3)-2 (메인/공통 영역 기능), 3)-3 (프로젝트 제안룸 기능)

**PPT 권장 구성**: 1장 — 이중 영역 구조 다이어그램 + 영역별 비교 표

---

### 1.2 영역 연계 구조

**헤드라인 메시지** 영역 간 자산 흐름과 지식공유 채널을 통한 통합 연계

**핵심 메시지** 프로젝트 산출물이 공통 영역의 자산으로 이어지는 데이터 흐름을 정의하고, 통합 검색을 통해 조직 내 지식공유를 활성화하며, 향후 확장 가능한 구조로 설계한다.

#### 가. 영역 연계의 필요성

영역 분리만으로는 시스템의 가치가 완성되지 않는다. 프로젝트 산출물이 공통 자산으로 흘러가는 흐름과, 자산이 다시 검색·활용되는 채널이 함께 정의되어야 자산 재활용이 작동한다.

#### 나. 영역 간 자산 흐름

- **자산화 흐름**: 프로젝트 제안룸의 최종 산출물 → 자산화 검토 → 공통 영역 자산 등록 _(상세는 3장)_
- **자산 활용 흐름**: 공통 영역의 표준 목차·템플릿·우수 제안서 → 프로젝트 제안룸 작성 시 참조

#### 다. 통합 검색 기반 지식공유

조직 내 지식공유 활성화를 위해 검색 채널을 이중화한다.

- **포털 통합검색**: 자산화된 제안 자료를 조직 전체가 발견 가능 (지식공유 채널)
- **제안룸 내 검색**: 프로젝트 작업 중 자료 회수
- 세부 정의는 5장(검색 체계)에서 다룸

#### 라. 향후 확장성

본 시스템은 향후 확장 가능한 구조로 설계한다.

- **영역 추가**: 신규 영역 도입 시 동일 권한·자산 체계 재활용
- **외부 시스템 연계**: 메타데이터·검색 API를 통한 타 시스템 연결 여지

**RFP 매핑**: 1)-1 (재활용 방안), 1)-2 (협업·관리체계), 1)-3 (확장성 고려), 1)-5 (지식공유 활성화)

**PPT 권장 구성**: 1장 — 영역 간 자산 흐름 다이어그램 + 통합 검색 이중화 도식 + 확장성 명시

# 2장. 권한·보안 체계

### 장 도입

**포털 통합 권한체계 기반의 보안·이력관리 통합 구축**

권한·보안 체계는 포털 시스템과 통합된 권한 모델을 기반으로 사용자 유형별 차등 접근통제와 행위 이력관리를 제공한다. 단일 권한 모델을 통해 포털과 제안룸의 권한 관리를 일관되게 운영하며, RFP 1)-4(통합 권한체계 방향), 2)(권한관리 및 접근통제), 4)(보안 및 이력관리) 요구사항을 통합 대응하기 위해 2가지 축으로 구성한다.

|Sub-section|다루는 내용|RFP 매핑|
|---|---|---|
|2.1 통합 권한체계|포털 연계 권한 모델 + 사용자 유형 정의|1)-4, 2)-1, 2)-2|
|2.2 접근통제 및 이력관리|접근통제 정책 + 행위 이력관리|2)-3, 4)-1, 4)-2, 4)-3|

---

### 2.1 통합 권한체계

**헤드라인 메시지** 포털 연계 통합 권한 모델 기반 사용자 유형별 권한 관리

**핵심 메시지** 포털 시스템과 단일 사용자/역할 모델을 공유하여 권한 관리의 일관성을 확보하고, 향후 타 시스템 확장 시에도 적용 가능한 표준 모델로 설계한다.

#### 가. 통합 권한체계의 필요성

제안룸이 포털과 별도의 권한 모델을 운영하면 사용자별 권한 관리·동기화 부담이 커지고, 권한 불일치로 인한 보안 사각지대가 발생한다. 포털과 단일 사용자/역할 모델을 공유하여 권한 관리의 일관성을 확보한다.

#### 나. 포털 시스템 연계 방식

- **SSO**: 포털 인증을 그대로 활용 (별도 로그인 불필요)
- **권한 동기화**: 포털 사용자·조직·역할 변동을 제안룸 권한에 자동 반영
- **사용자 라이프사이클 연계**: 입·퇴사 등 사용자 변경에 따른 권한 자동 갱신

#### 다. 사용자 유형 정의

|사용자 유형|정의|주요 권한 범위|
|---|---|---|
|**일반사용자**|포털 인증된 일반 임직원|공통 영역 일부 자산 조회|
|**제안룸 사용자(임직원)**|프로젝트 제안룸에 등록된 임직원|해당 제안룸의 산출물 등록·조회·수정|
|**협력사**|프로젝트 제안룸에 등록된 외부 협력사 인력|지정 영역·산출물 조회 (제한적)|
|**운영자**|제안룸 운영·관리 권한자|제안룸 예약 승인, 자산 등록 승인 등|

#### 라. 권한 모델 (Role 기반)

- **Role 정의**: 사용자 유형별 기본 권한 묶음
- **권한 항목**: 영역(공통/프로젝트) × 행위(조회/등록/수정/다운로드) × 자산 유형
- **권한 매트릭스**: 사용자 유형 × 권한 항목을 매트릭스 형태로 가시화

#### 마. 확장 청사진

본 사업의 통합 권한관리 모델은 향후 타 시스템 확장 시에도 동일 권한체계 적용 가능한 표준 모델로 설계한다. 제안룸 도입을 시작점으로 점진적인 권한체계 통합을 지원한다.

**RFP 매핑**: 1)-4 (통합 권한체계 설계 + 우선 적용), 2)-1 (사용자 유형 구분 관리), 2)-2 (포털 연계 통합 권한)

**PPT 권장 구성**: 1장 — 좌측 사용자 유형 표 + 우측 권한 매트릭스 도식 + 하단 포털 연계 방식

---

### 2.2 접근통제 및 이력관리

**헤드라인 메시지** 사용자 유형·영역별 접근통제 및 행위 이력관리 통합 운영

**핵심 메시지** 권한체계를 기반으로 영역과 사용자 유형에 따른 차등 접근통제를 적용하고, 주요 행위에 대한 이력관리를 통합 운영하여 사업수주 및 지적재산 보호 요건을 충족한다.

#### 가. 접근통제와 이력관리를 함께 다루는 이유

차등 접근통제는 사전 보안(누가 무엇을 볼 수 있는가)을 정의하고, 행위 이력관리는 사후 추적(누가 무엇을 했는가)을 보장한다. 두 기능이 함께 운영될 때 자산의 보안과 지적재산 보호가 완성되므로 동일 sub-section에서 통합 설계한다.

#### 나. 접근통제 정책

**1) 영역별 접근통제**

|영역|접근 원칙|
|---|---|
|공통 영역|권한 부여된 사용자 유형만 조회 (자산 유형별 차등 적용 가능)|
|프로젝트 제안룸|등록된 구성원만 접근, 협력사는 지정 영역·산출물에 한정|

**2) 사용자 유형별 정보 접근 및 다운로드 제한**

|사용자 유형|접근 범위|다운로드|
|---|---|---|
|일반사용자|공통 영역 일부 자산|제한 적용|
|제안룸 사용자(임직원)|등록된 제안룸의 모든 자산|일반 다운로드|
|협력사|지정된 영역·산출물|제한 적용|
|운영자|운영 권한 범위 내 자산|일반 다운로드|

세부 다운로드 제한 정책은 운영 정책 문서로 관리한다.

**3) 검색 결과 차등 (5장 연계)**

검색 시 사용자 권한에 따라 검색 결과를 차등 노출한다. 권한 없는 자산은 결과에서 미노출하며, 세부 노출 정책은 5장(검색 체계)에서 정의한다.

#### 다. 행위 이력관리

**1) 이력 관리 대상 행위**

- 산출물 등록 / 수정 / 삭제
- 산출물 조회 / 다운로드
- 권한 변경 / 자산 게시·비공개

**2) 로그 항목**

|항목|내용|
|---|---|
|행위자|사용자 ID / 사용자 유형 / 소속|
|시점|행위 발생 일시|
|대상|자산 / 영역 / 제안룸|
|행위 유형|등록·조회·수정·삭제·다운로드 등|

**3) 이력 데이터 활용**

- **보안 감사**: 지적재산 보호 관점의 사후 추적
- **운영 관리**: 제안룸 활동 모니터링 (6장 운영관리에서 활용)

**RFP 매핑**: 2)-3 (권한·검색 위치별 차등), 4)-1 (승인된 사용자만 접근), 4)-2 (사용자 유형별 접근·다운로드 제한), 4)-3 (주요 행위 이력관리)

**PPT 권장 구성**: 1~2장

- 슬라이드 A: 접근통제 정책 (영역별 + 사용자 유형별 차등 매트릭스)
- 슬라이드 B: 행위 이력관리 (대상 행위 + 로그 항목 + 활용)

# 3장. 공통 자산 관리

## 장 도입

**공통 자산의 등록·관리·갱신 통합 체계 구축**

## 3.1 공통 자산 구성 체계

**헤드라인 메시지** 활용 목적별 4가지 자산 유형 정의를 통한 공통 자산 구성

**핵심 메시지** 공통 영역의 자산을 활용 목적별로 4가지 유형으로 분류하여 등록·검색·갱신 단계에서 유형별 차등화된 관리 기준을 적용한다.

### 가. 자산 분류의 필요성

자산을 단일 형태로 관리하면 활용 목적이 다른 자료가 섞여 검색·갱신·권한 관리 단계에서 혼란이 발생한다. 활용 목적을 기준으로 자산 유형을 구분하고, 유형별 관리 방식을 차등화한다.

### 나. 자산 4유형 정의

|자산 유형|정의|활용 시점|관리 특성|
|---|---|---|---|
|**표준 제안 목차**|사업유형을 포괄하는 제안서 표준 구조|프로젝트 제안룸 생성 시 시작점 _(4장 연결)_|통합 관리, 운영자 갱신|
|**제안 템플릿**|표준 목차에 작성 가이드·예시를 포함한 양식|신규 제안 작성 시 기본 양식|사업유형별 다수 운영|
|**우수 제안서**|평가를 거쳐 선정된 참고용 완성 제안서|유사 사업 제안 시 참고 자료|선정 절차 운영|
|**최종 산출물**|프로젝트에서 확정된 제안 자료 전체|사업 추진 이력 / 후속 제안 기반|변경 제한, 이력 보존|

### 다. 자산 간 관계 _(다이어그램으로 시각화)_

- 표준 제안 목차 ─(양식화)→ 제안 템플릿
- 프로젝트 제안룸 산출물 ─(자산화 검토)→ 최종 산출물 등록
- 최종 산출물 ─(평가·선정)→ 우수 제안서 등재

**RFP 매핑**: 5)-1 (자산 통합 관리), 5)-2 (표준 제안 목차)

**PPT 권장 구성**: 1장 — 좌측 자산 4유형 표 + 우측 자산 간 관계 도식

## 3.2 자산화 워크플로우 및 메타데이터 관리체계

**헤드라인 메시지** 자산화 워크플로우 및 메타데이터 관리체계 구축

**핵심 메시지** 산출물을 자산으로 등록하는 표준 프로세스와 메타데이터 체계를 통해 자산 등록의 일관성과 검색 가능성을 확보한다. 메타데이터 체계는 자산 검색·재활용을 가능하게 하는 기반 요소다.

### 가. 워크플로우와 메타데이터를 함께 다루는 이유

자산화는 등록 행위만으로 완성되지 않는다. 누가, 언제, 어떤 정보와 함께 등록하는지가 정해져야 등록 자산이 일관되게 관리되고 검색에서 활용된다. 등록 프로세스(워크플로우)와 등록 정보 표준(메타데이터)을 두 축으로 함께 설계한다.

### 나. 자산화 워크플로우

**자산화 4단계**

|단계|활동|책임자|
|---|---|---|
|① 프로젝트 종료|제안룸 최종 산출물 확정|프로젝트 리더|
|② 자산화 검토|자산 등록 가치·보안 분류 판단|프로젝트 리더|
|③ 메타데이터 부여|사업유형·규모·특성 입력|등록자|
|④ 공통 영역 등록|자산 등록 승인 및 게시|운영자|

**자산화 시점**

- 프로젝트 종료 시 자산화 후보 자동 등록
- 운영자 승인을 거쳐 공통 영역 게시
- 운영 중에도 수동 자산화 신청 가능

**등록 시 검증 포인트**

- 메타데이터 필수 항목 입력 여부
- 자산 분류값 유효성
- 동일·유사 자산 중복 여부

### 다. 메타데이터 스키마

|구분|항목|입력 방식|
|---|---|---|
|**분류 메타데이터** _(RFP 명시)_|사업유형, 사업규모, 프로젝트 특성|등록자 입력 (표준 분류값 선택)|
|**시스템 메타데이터**|작성자, 등록일, 자산 유형, 버전, 권한 분류|시스템 자동 수집|

**확장 가능 구조**: 운영 중 항목 추가 시 시스템 변경 없이 메타데이터 정의 갱신만으로 대응

### 라. 메타데이터 운영 모델

|운영 요소|내용|
|---|---|
|**입력 표준 가이드**|사업유형 분류 체계, 규모 구간 정의 등 — 운영 정책 문서로 관리|
|**등록 시 검증 룰**|필수 항목 입력 강제, 분류값 유효성 자동 검증|
|**정합성 점검**|운영자 정기 점검 (점검 주기는 운영 정책으로 정의)|

**RFP 매핑**: 5)-1 (자산 등록), 9)-1 (사업유형·규모·특성), 9)-2 (메타데이터 일관성·정합성)

**PPT 권장 구성**: 1~2장

- 슬라이드 A: 자산화 워크플로우 4단계 도식 + 단계별 책임자
- 슬라이드 B: 메타데이터 스키마 표 + 운영 모델

## 3.3 자산 변경 및 품질 관리

**헤드라인 메시지** 변경이력 관리와 우수 자산 갱신 사이클을 통한 자산 가치 유지

**핵심 메시지** 등록 자산의 신뢰성과 활용 가치를 유지하기 위해 변경이력 추적과 우수 자산 선정·갱신 사이클을 운영한다.

### 가. 변경관리·품질관리의 필요성

자산은 시간이 지나면서 가치가 변한다. 사업 환경 변화로 노후화되거나 일부 정정이 발생하면 어떤 자산이 신뢰할 만한지 판단할 기준이 필요하다. 변경이력 추적과 우수 자산 갱신을 운영 사이클로 정의한다.

### 나. 변경이력 및 버전 관리

|관리 단위|관리 항목|
|---|---|
|**자산 단위**|등록·수정·삭제 행위 / 작업자 / 시점 / 변경 사유|
|**항목 단위**|메타데이터 변경 / 첨부 파일 변경 / 권한 변경|

**버전 관리 정책**

- 주요 변경 시 버전 갱신
- 이전 버전 조회 가능
- 자산별 변경 이력 화면 제공

### 다. 우수 제안서 선정 및 갱신

**선정 기준** _(운영 정책 문서로 관리)_

- 사업 수주 결과
- 제안 평가 점수
- 재활용 빈도

**갱신 사이클**

- 정기 검토: 연 1회 우수 제안서 목록 재평가
- 비정기 갱신: 신규 우수 제안서 추가 / 노후화 자산 비활성화

### 라. 표준 제안 목차 개선

표준 제안 목차는 운영 데이터를 기반으로 주기적으로 개선한다.

- **현장 사용 결과**: 사업유형별 자주 추가·삭제되는 항목 분석
- **변형 패턴 분석**: 프로젝트 제안룸의 목차 수정 데이터 활용
- **정기 개선**: 운영자가 데이터 기반으로 개선안 도출 → 표준 목차 갱신

**RFP 매핑**: 5)-2 (지속 개선), 5)-3 (변경이력·유형별 관리)

**PPT 권장 구성**: 1장 — 좌측 변경이력·버전 관리 + 우측 우수 자산 갱신·목차 개선 사이클

프로젝트 제안룸은 프로젝트 단위 제안서 작성·협업·확정을 위한 작업 공간이다. 제안 과정의 계획·실행·산출물 관리 흐름에 따라 3단계로 기능을 구성하여 RFP 1)-2(협업·관리체계)와 6)(프로젝트 제안룸 기능) 요구사항을 통합 대응한다.

### 4.1 제안 계획

**헤드라인 메시지** 제안룸 구성과 표준 목차 기반 제안 계획 수립

**핵심 메시지** 프로젝트 제안룸을 구성원·표준 목차·담당자·일정으로 정의하여 제안 작성의 기반을 마련한다.

#### 가. 제안 계획 단계의 구성

제안 작성 시작 전에 누가, 어떤 항목을, 언제까지 작성할 것인가가 정의되어야 작성 과정이 체계적으로 운영된다. 계획 단계는 구성원 등록, 목차 정의, 담당자 지정, 일정 수립의 4가지 활동으로 구성한다.

#### 나. 제안룸 생성 및 구성원 등록

- **제안룸 생성**: 운영자 승인을 거쳐 생성 (6장 운영관리에서 상세)
- **구성원 등록**: 임직원 + 협력사 등록, 역할 부여
- **권한 적용**: 사용자 유형별 접근 권한 자동 적용 (2장 연계)

#### 다. 표준 목차 적용 및 변형

- 제안룸 생성 시 공통 영역의 표준 제안 목차 자동 적용 (3장 연계)
- 프로젝트별 항목 수정·삭제·추가 가능
- 변형 데이터는 운영 데이터로 수집되어 표준 목차 개선에 활용 (3장 3.3 연계)

#### 라. 작업담당자 지정 및 일정 수립

- **담당자 지정**: 목차 항목별 작업담당자 배정
- **일정 수립**: 제안 전체 마감일 + 항목별 마감일
- **변경 관리**: 담당자·일정 변경 시 변경 이력 기록

**RFP 매핑**: 6)-1 (구성원 등록·관리), 6)-2 (표준 목차 기반 구성, 담당자 지정)

**PPT 권장 구성**: 1장 — 좌측 제안 계획 4단계 (구성원 / 목차 / 담당자 / 일정) + 우측 제안룸 생성 화면 예시

### 4.2 제안 실행

**헤드라인 메시지** 산출물 등록·관리와 진도관리를 통한 협업 운영

**핵심 메시지** 목차 항목별 산출물 등록·관리와 작성 현황·기간 기반 진도관리로 제안 작성 과정을 운영한다.

#### 가. 실행 단계의 구성

계획에 따라 작성된 결과물을 등록·관리하고, 작성 현황을 가시화하여 운영 가능하게 만든다. 실행 단계는 산출물 관리와 진도관리 두 축으로 구성한다.

#### 나. 목차 항목별 산출물 관리

- 목차 항목별 산출물 등록·수정·삭제
- 산출물 버전 관리 (작성 중 단계의 변경 이력)
- 산출물 첨부 파일 관리

#### 다. 진도 관리

|관리 차원|내용|
|---|---|
|전체 진도|제안 마감일 대비 전체 작성 현황|
|항목별 진도|목차 항목별 작성 상태 (작성 중 / 검토 / 완료)|
|담당자별 진도|담당자별 진행률|

#### 라. 협업 지원

- 담당자 변경, 일정 조정 등 협업 활동
- 활동 알림 (담당자 지정, 마감일 임박 등)

**RFP 매핑**: 6)-3 (목차 항목별 산출물 관리), 6)-4 (진도관리)

**PPT 권장 구성**: 1장 — 좌측 산출물 관리 + 우측 진도관리 대시보드 예시

### 4.3 산출물 확정

**헤드라인 메시지** 최종 산출물 확정과 변경이력 관리

**핵심 메시지** 최종 산출물의 확정 처리와 변경이력 관리를 통해 산출물의 신뢰성을 확보하고, 자산화 후보로 연결한다.

#### 가. 확정 단계의 구성

작성·검토를 거친 산출물을 최종 확정하여 제안룸의 결과물로 고정하고, 이후 자산화 흐름으로 연결한다.

#### 나. 최종 산출물 확정 처리

- **확정 권한자 지정**: 제안룸별 확정 권한자 사전 정의
- **확정 처리**: 권한자가 산출물별로 최종 확정
- 확정 후에는 변경 제한 (변경 시 별도 절차 적용)

#### 다. 변경이력 관리

|관리 단위|관리 항목|
|---|---|
|산출물 단위|등록·수정·확정 행위 / 작업자 / 시점|
|항목 단위|메타데이터 변경, 첨부 파일 변경|

#### 라. 자산화 후보 등록 (3장 연계)

- 확정된 최종 산출물은 자산화 후보로 자동 등록
- 자산화 검토 → 메타데이터 부여 → 공통 영역 등록 흐름 진행 (3장 자산화 워크플로우)

**RFP 매핑**: 6)-5 (최종 산출물 확정 + 변경이력 관리)

**PPT 권장 구성**: 1장 — 좌측 확정 처리 흐름 + 우측 변경이력 + 자산화 연결 도식
