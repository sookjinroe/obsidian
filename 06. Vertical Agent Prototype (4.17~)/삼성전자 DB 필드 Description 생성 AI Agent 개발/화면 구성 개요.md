### 1. 대시보드
전체 처리 현황 한눈에
총 컬럼 수, Description 생성 완료/미완료 비율, Confidence 분포(high/medium/low), 최근 실행 이력 등

- API 문서 → State(Creating/Producing/End/Fail)를 소스로 활용
- 데모 때는 처리 규모나 오버뷰로 활용

### 2. 실행 화면
언제 → 무슨 단위로 실행하냐
1. 레거시 정리할 때 → 전체(디스크립션 있던 없던)
2. 새 시스템이나 디비가 추가됐을 때 → 시스템 단위 전체
3. 스키마 변경 되었을 때 관련 디스크립션도 같이 업데이트하고 싶을 때 → 그 테이블
4. 특정 컬럼이 이상할 때 → 컬럼한개

- 실행 범위: 전체 / 시스템 / 테이블 / 컬럼
- Description 존재 여부: 없는 것만 / 전체(있는 것 포함)

- API 문서 → 테이블 단위로 request, 실행 범위는 화면에만 가짜로 넣거나 기능 좀 바꾸거나

### 4. 검토 화면

생성된 결과를 보고 판단하는 화면. 컬럼 목록에 Confidence 배지가 붙어 있고, 각 항목을 클릭하면 T/P/F 구성과 근거(어떤 소스에서 왔는지)가 보여요.

액션은 두 가지 방향:

- **승인/반려/수정** — 반려는 자동 재생성 트리거와 사유 입력 후 수동 재실행 두 옵션. 수정은 직접 편집 후 확정.
- **내보내기** — 다운로드(JSON)와 DB 반영 두 옵션.

**근거** — 검증 문서의 HITL(Human in the Loop) 항목이 이 화면의 존재 이유예요. Confidence low는 사람이 봐야 하는데, 그 판단을 하려면 근거가 보여야 해요. 내보내기 두 옵션은 "특정 카탈로그에 종속되지 않는 독립 레이어"라는 작업목표의 포지션을 UI에서 직접 보여주는 장치예요.
