# 목적

- LLM이 생성한 결과물에 대한 검증 방안

  

# 내용

| 분류                                  | 항목                                                                    | 내용                                                           | 비고  |
| ----------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------ | --- |
| Output 기준                           | LLM을 N번 수행하여 M번의 일관된 답변을 채택                                           | - LLM을 같은 inference를 여러번 수행하여 투표해서 선정하거나, threshold를 충족하면 채택 |     |
| 구조/형식 검증                            | - 기대한 format / output으로 나왔는지 검증                                       |                                                              |     |
| LLM-as-a-Judge                      | - 평가자 LLM을 두고 결과를 평가                                                  |                                                              |     |
| input 데이터 활용 여부 검증(Grounding Check) | - 실제 검색된 문서를 인용하여 결과를 만들어냈는가                                          |                                                              |     |
| 규칙 기반후처리                            | - 결과가 허용 범위 내의 값인지                                                    |                                                              |     |
| Hunman in the loop                  | - 사람이 검증                                                              |                                                              |     |
| Input 기준                            | Input 데이터에 대한 checklist                                               | - input data가 품질이 좋은 output을 낼 수 있는 필수 조건을 충족하는지 검증하는 방식     |     |
| 입력 내용이 실제로 의미 있는 데이터?               | - 임베딩 유사도를 통해 입력 데이터가 도메인 범위 안에 있는 데이터 인지 검증 <br>- 가비지 텍스트, 프롬프트를 필터링 |                                                              |     |
| 토큰 수 / 비용을 초과하지 않는지                 | - Context Window 를 초과하는 경우 입력이 잘릴 수 있음<br>- Chunking 필요               |                                                              |     |
