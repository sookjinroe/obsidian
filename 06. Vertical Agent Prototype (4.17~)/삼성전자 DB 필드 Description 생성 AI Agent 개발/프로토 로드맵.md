# 프로토타입 설계

_Companion document to `작업목표.md`, `제품_구성.md`. 이 문서는 "어떻게 보여주는가(how-to-sell)"를 다룬다._

---

## 1. 프로토타입의 목적

**셀링 가능한 프로토타입**을 만드는 것이 목표다. 완성된 운영 도구가 아니라, 고객이 "이런 게 가능하구나"를 체감하게 만드는 도구다.

두 가지 조건을 만족해야 한다.

1. **작업 과정이 보여야 한다** — 블랙박스로 돌고 결과만 받아보는 구조는 차별점이 전달되지 않는다
2. **도구가 인상적이어야 한다** — 결과가 좋다는 설명보다 직접 돌아가는 걸 보여주는 게 훨씬 강하다

차별점은 단일 기능이 아니라 **"채우기 → 용어집 유지 → 변화 감지"로 이어지는 레이어 전체의 작업 흐름**이다. 프로토는 이 흐름의 맛보기를 담는다.

## 2. 시연 시나리오 (4개)

고객의 용어집 상태(Case 1/2/3)에 따라 제품이 다르게 작동하는 걸 각 시나리오가 보여준다.

### 시나리오 A — Description 생성 (Case 1·3 대응)

**메시지**: 카탈로그가 혼자 할 수 없는 일, 우리가 한다

```
빈 컬럼 투입 (예: flg_tax_exmp)
  ↓
L0 타 시스템 재활용 시도 → 실패
L1 용어집 조립 시도 → 부분 성공 (tax, exmp만 매칭)
L2 스키마·샘플값 참조 → 값이 Y/N/P/X
L3 소스코드 뒤집 → Enum 발견 (Y=면세, N=과세, P=부분면세, X=해당없음)
  ↓
Description 완성 + Confidence + 출처
```

**체감 포인트**: LLM이 여러 레벨로 에스컬레이션하며 단서를 수집하는 과정 자체가 차별점. 단일 LLM 호출이 아니라 단계적 전략임을 보여준다.

### 시나리오 B1 — 용어집 Bootstrap (Case 2 대응)

**메시지**: 용어집이 없어도 시작할 수 있다

```
사용자가 "용어집 Bootstrap" 실행
  ↓
전체 소스코드·DB 스키마 일괄 스캔
  ↓
LLM이 패턴 분석:
  - 컬럼명에 반복되는 약어 식별 (cust, reg, dt, flg...)
  - 소스코드 Enum·변수명에서 확장형 발굴
  - 도메인 맥락 추정
  ↓
수백~수천 개 용어 후보 일괄 생성
  ↓
Steward 일괄 검토 UI → 승인/거절/수정
  ↓
용어집 완성 → 이후 시나리오 A에 활용
```

**체감 포인트**: "9~12개월 걸리는 수작업을 몇 분 만에 끝낸다"는 Bootstrap의 임팩트. 용어집이 비어 있는 조직(Case 2)이 제품 도입의 벽을 넘을 수 있게 해준다.

### 시나리오 B2 — 용어집 운영 보강 (Case 3 대응)

**메시지**: 쓰는 동안 용어집이 스스로 진화한다

```
시나리오 A 실행 중
  ↓
Vocabulary Builder가 용어집 gap 감지:
  - "pkg이 컬럼명에 자주 나오는데 용어집에 없음"
  - "소스코드 Enum에 새 개념(PARTIAL_EXEMPT) 발견"
  ↓
백그라운드에서 후보 자동 등록
  → 근거 수집 (어느 파일 어느 위치)
  → 검토 큐로 이동
  ↓
Steward가 틈틈이 검토 → 승인 시 용어집 반영
  → 다음 컬럼 처리 시 품질 상승
```

**체감 포인트**: "한 번 만들고 끝이 아니라 계속 좋아진다"는 지속 가치. 운영 구독 모델의 근거가 되는 시나리오.

### 시나리오 C — 변화 감지

**메시지**: 로드맵 2·3단계 가치 체감

```
기존 Enum이 Y/N/P/X 4개
  ↓
소스코드에 새 값 D(delayed) 추가됨 감지
  ↓
영향받는 Description 자동으로 재생성 큐에 올림
  ↓
기존 vs 신규 비교 뷰
  ↓
검토자 승인 → 카탈로그 업데이트
```

**체감 포인트**: "만들고 끝"이 아니라 "살아있게 유지"된다는 메시지.

## 3. 프로토 4단계 로드맵

시나리오 구현 우선순위를 구현 난이도와 셀링 임팩트를 고려해 4단계로 나눈다.

### 1차 — 시나리오 A + B2-lite

**A 완전 구현**

- 실시간 추론 경로 시각화
- Confidence·출처 역추적
- Case 1·3 고객 대응 가능

**B2-lite (UI 메시지만)**

- A의 추론 경로 중 "용어집 gap 감지 → 후보 등록" 상태 메시지 추가
- 실제 Lexis 엔진은 백엔드 구현 생략, 시연용 mock
- 운영 시 자동 보강된다는 인상 전달

**데모 스크립트**

- "실제 시나리오 A가 돌아갈 때 이런 gap이 자동으로 잡힙니다"
- "이것들이 쌓이면 2차에서 보여드릴 Bootstrap·보강 기능으로 연결됩니다"

### 2차 — 시나리오 B1 (용어집 Bootstrap)

**독립 플로우로 구현**

- 대규모 스캔 UI (진행률, 발견된 후보 수)
- 후보 일괄 검토 UI (카테고리·도메인별 그룹핑)
- 승인/거절/수정 → 용어집 반영
- 진짜 Vocabulary Builder 엔진 구현

**타깃 고객**

- 용어집이 거의 비어 있는 조직 (Case 2)
- 신규 시스템 도입 시

### 3차 — 시나리오 B2 완전 구현

**1차의 mock을 실제 엔진으로 교체**

- A 실행 중 자동 발동
- 검토 큐 관리 UI
- 근거 역추적 (어느 파일·어느 위치에서 발굴됐는지)

### 4차 — 시나리오 C (변화 감지)

**운영 레벨 지속 관리**

- 스키마 diff 감지
- 소스코드 변경 감지
- 영향 범위 자동 계산 + 재생성 큐
- 기존 vs 신규 비교 뷰

## 4. 모듈별 애니메이션 루프

Atlan 벤치마크. 홈페이지나 시연 화면에서 **짧은 애니메이션을 반복 재생**하여 각 모듈이 무엇을 하는지 직관적으로 전달한다.

|모듈|애니메이션 내용|길이|
|---|---|---|
|M1 Description Composer|컬럼명 → 여러 레벨로 에스컬레이션 → 완성|15초|
|M1 Vocabulary Builder|소스코드 스캔 → 새 용어·약어 발견 → 용어집 후보 등록|10초|
|M2 Context Enricher|테이블 컬럼들 모음 → README 생성|10초|
|M3 Sync Manager|스키마 변경 감지 → 영향 범위 표시 → 재생성|10초|
|M4 Quality Inspector|생성 결과 검증 → Low confidence 분류 → HITL 큐|10초|

### 설계 원칙

- **실제로 돌아가는 것처럼 보이되 간결하게** — 10~15초 루프가 차별점 전달에 효과적
- **반복 재생 가능해야 함** — 고객이 여러 번 돌려보며 이해하는 구조
- **단순 결과가 아니라 과정을 보여줘야 함** — "빈 컬럼 → 완성" 점프컷이 아니라 중간 단계를 노출

### 고유 시연 포인트: M1 내부의 레벨 에스컬레이션

Atlan은 에이전트 9개를 각각 시각화한다. 우리는 모듈이 4개로 상대적으로 적지만, **M1 내부에 여러 레벨로 순차 시도되는 애니메이션**은 우리만의 고유 시연 포인트다.

> "Atlan은 하나의 생성 방식인데, 우리는 단서 레벨에 따라 에스컬레이션한다"

이 메시지가 애니메이션 하나로 전달된다.

## 5. UI 구성 요소

### 메인: 실시간 추론 경로 스트리밍

시나리오 A가 실행될 때 사용자가 보는 기본 뷰. 내부 레벨 용어는 노출하지 않고 자연어 상태 메시지로 표현.

```
┌─────────────────────────────────────────┐
│ 현재 처리 중: flg_tax_exmp              │
├─────────────────────────────────────────┤
│ ○ 다른 시스템에서 같은 컬럼 확인 중     │
│   → 재활용 가능한 설명 없음 (0.3s)      │
│ ● 용어집에서 의미 조립 중...            │
│   → "tax"는 '세금'과 높은 연관성        │
│   → "exmp"는 '면제'의 약어로 해석       │
│   → "flg"는 '플래그'로 해석             │
│ · 구조 힌트 확인          대기          │
│ · 소스코드 맥락 분석      대기          │
└─────────────────────────────────────────┘
```

B2-lite 표현 (1차에 포함)

```
┌─────────────────────────────────────────┐
│ 용어집 보강 발견                        │
│ → "pkg" 약어가 용어집에 미등록          │
│ → 소스코드에서 "package" 확장형 발견    │
│ → 용어집 후보로 등록 (검토 대기 3건)    │
└─────────────────────────────────────────┘
```

### 서브: 출처 역추적 뷰

Description 하나를 선택하면 어떤 데이터가 어떻게 쓰였는지 역추적.

```
세금면제상태코드
├─ "세금"    ← 용어집 (glossary_v2, 2024-03-15)
├─ "면제"    ← 용어집 (glossary_v2, 2024-03-15)
└─ "상태코드" ← 소스코드 Enum (TaxExemption.java:42)
```

### 사이드: Governance Console 맛보기

운영 레벨로 확장되면 어떤 관리자 화면이 되는지 암시하는 작은 패널.

```
┌─── 전체 처리 현황 ───┐
│ 총 대상 │ 10,234  │
│ 완료   │ 8,401   │
│ 진행중  │ 42      │
│ 검토필요 │ 1,791   │
│                     │
│ Confidence 분포     │
│ High   62%          │
│ Medium 28%          │
│ Low    10% (검토큐) │
└─────────────────────┘
```

## 6. 프로토 vs 운영 UI의 차이

같은 기반 데이터(추론 경로·출처·confidence)를 공유하지만 목적이 다르다.

||프로토|운영 (Governance Console)|
|---|---|---|
|주 사용자|잠재 고객 (시연 관람)|검토자·데이터 담당자|
|초점|화려함, 실시간 스트리밍|검색·필터링·대량 처리|
|범위|한두 개 컬럼 집중|수천~수만 건 일괄 관리|
|기능|"보여주기"|"찾기·판단·승인·감사"|

## 7. 셀링 시나리오 흐름

전체 시연을 30분 단위로 구성할 때.

|단계|내용|시간|
|---|---|---|
|오프닝|문제 정의: 카탈로그가 있어도 Description이 비면 AI 분석 불가|3분|
|시나리오 A|Description 생성 데모 (다단계 에스컬레이션)|7분|
|B2-lite 언급|운영 중 용어집이 자동으로 진화함을 UI 메시지로 노출|2분|
|시나리오 B1 (2차 이후)|용어집 Bootstrap 데모|5분|
|시나리오 C (4차 이후)|변화 감지 맛보기|3분|
|커버리지 비교|Atlan 대비 포지셔닝|4분|
|Q&A||6분|

핵심은 **"단계가 쌓여가며 차별점이 누적되는 구조"** 다. 시나리오 A만으로는 Atlan과 크게 다르지 않아 보이지만, B1·B2·C로 가면서 우리의 고유 영역이 드러난다.

1차 프로토에서도 A + B2-lite만으로 **"용어집이 없어도/부실해도 작동한다"** 는 메시지 전달 가능.
