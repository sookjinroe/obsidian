### langgraph state 와 ui observability 연결 

1. 에이전트가 뭘 봤는지를 드러낼 것
	- 에이전트가 무언가를 하고 있다는 건 알지만 왜 그런 결정을 내렸는지 알 수 없음
	- 진행 상태만 보이는 시스템은 블랙박스로 인식되어 신뢰 상실
	→ "용어집 조회 → 미매칭 → 소스코드 Enum 확인"은 파이프라인이 이미 아는 정보, 노드 실행 결과를 State에 메타데이터로 넣기

2. 생성 결과를 출처로 역추적 가능하게
	- 결과물이 좋아도 어디서 나왔는지 모르면 지어낸 것과 구분 불가
	- T/P/F 각 요소가 91개 표준항목 / 용어집 / 소스코드 Enum 중 어디서 왔는지
	- 출처 메타데이터는 파이프라인 레벨에서 적재 가능

3. Confidence를 액션 분기 기준으로 사용
	- 신뢰도가 색깔로만 표시되면 결국 사용자가 전수 검토. 대규모 처리에서 HITL의 의미가 사라짐
	- 예: High → 자동 승인 후보, Low → 검토 큐로 기본 라우팅
	- Confidence 판정 + 이유는 Description 생성과 동시에 structured output으로 추출 가능하지 않을지?

4. 결과가 약할수록 UI가 더 설명할 것
	- 설명되지 않은 단 한 번의 실패가 누적된 성공을 무효화
	- Low confidence 결과에서 이유가 안 보이면 모르는걸 모른다고 한건데(이것도 어려움) → 사용자는 오류로 인식됨
	- "컨텍스트 부족 / 용어집 미등록 / 소스코드 참조 없음"은 파이프라인 레벨 플래그로 구현
	- confidence Low일수록 UI가 더 많은 메타데이터를 노출해야함
