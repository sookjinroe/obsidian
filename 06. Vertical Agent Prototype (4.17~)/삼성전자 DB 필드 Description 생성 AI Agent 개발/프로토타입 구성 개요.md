### 1. 실행 요청
언제 → 무슨 단위로 실행하냐
1. 레거시 정리할 때 → 전체(디스크립션 있던 없던)
2. 새 시스템이나 디비가 추가됐을 때 → 시스템 단위 전체
3. 스키마 변경 되었을 때 관련 디스크립션도 같이 업데이트하고 싶을 때 → 그 테이블
4. 특정 컬럼이 이상할 때 → 컬럼한개

- 실행 범위: 전체 / 시스템 / 테이블 / 컬럼
- Description 존재 여부: 없는 것만 / 전체(있는 것 포함)

- API 문서 → 테이블 단위로 request, 실행 범위는 화면에만 가짜로 넣거나 기능 좀 바꾸거나

### 2. 진행 추적
실행요청이 큐에 쌓이고 처리되는 동안 지금 뭐가 돌아가고 있고, 뭐가 끝났는지 실시간 조회
- 활성 Job 목록, 각 Job의 진행률, 완료된 Job 이력 등
- 이미 구현된거같은데 과한 기능일지..? 화면엔 어차피 데이터는 가짜로 넣으면 되긴함

### 3. 추론 과정 관찰
에이전트가 개별 컬럼을 추론/작업하는 과정 보여주기 → 데모에 필요한 것
- 에이전트가 뭘 보고 무슨 판단을 했는지
	- 용어집, 표준 어쩌구 91개 매핑, 소스코드 등
	- confidence level 판정
	- 디스크립션
- 배치 실행할텐데 데모는 1건의 처리 과정을 보여줘야함. 
	- 실제 서비스는 배치일텐데.. 배치 리스트에서 상세 영역 볼수있게 하면 될지? 데모에만 필요해서
- 에이전트 레벨에서 Observability 설계 필요(langgraph state)
	- 근데 지금 컨플에서는 추론 과정이 없음(못찾음) → 이걸 실제로 안하는지 보여줄 방법 없을 지 고민 필요 → 누가 만들었는지?


### 4. 결과 검토

생성된 결과를 사람이 보고 승인/반려/수정
컬럼 목록에 Confidence 배지가 붙어 있고
각 항목을 클릭하면 T/P/F 구성과 근거(어떤 소스에서 왔는지)

차라리 추론 과정 관찰(1건 실행 순서 착착 진행되는거) 빼고 
결과 검토 화면으로 대체할수도? 반려된 것들 처리 과정 다 나오니까
그대신 데모 임팩트 약함

다운로드 or db에 반영
