컬럼 하나가 가지는 4가지 주소:

[물리 주소]   DB → Schema → Table → Column
[도메인 주소] Domain → Subdomain ─ 안에 소속
[시스템 주소] System ─ 안에 소속  
[의미 주소]  여러 Term들과 다대다로 link


[물리 hierarchy]   [도메인 hierarchy]    [시스템]    [Term hierarchy]
     ↓                                      ↓                          ↓                          ↓
     └────→  [컬럼 = 교차점]  ←────┘───link──┘

RAG 자료 메타데이터
전사 공용 자료
└─ 91 표준항목, 표준화 지침, 행안부 포맷
   (스코프 무관, 항상 적용)

도메인 종속 자료
└─ 시맨틱 레이어, 업무 규정
   (도메인이 자료의 정체성의 일부)

시스템 종속 자료
└─ 소스코드, 시스템 정보
   (시스템이 자료의 정체성의 일부)

자체 계층 자료
└─ 용어집 (Glossary → Category → Term)
└─ DB 스키마 (DB → Schema → Table → Column)
   (자료 자체의 구조가 1차 분류)

- Synonym 관계 (Customer ID ↔ Client ID — 같은 글로서리 안에 있으나 명시적 엣지는 생략)
- Term 간 더 많은 관계 (Antonym, Preferred, Translated)
- Confidence 등급·Verification 워크플로우
- Tag propagation이 lineage 따라 derived 자산까지 전파되는 흐름 (Tag · Lineage 연계)
- Cardinality 표시 (모든 link은 N:N으로 추가 가능)
