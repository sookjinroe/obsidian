## 진화 방향 ①. Generative UI — 화면 자체가 Agent의 출력물이 된다

### 개념

Generative UI는 Agent가 런타임에 인터페이스에 영향을 미치도록 허용하는 아이디어로, 컨텍스트가 변화함에 따라 UI가 변할 수 있다. 대부분의 Agent 경험은 오늘날 여전히 채팅 앱처럼 보인다. Agent가 채팅을 넘어 실제로 무언가를 시작하면, 텍스트만으로는 병목이 된다. [DEV Community](https://dev.to/copilotkit/the-developers-guide-to-generative-ui-in-2026-1bh3)

기존 UI 개발 패러다임에서 설계자는 모든 화면을 미리 만들어 놓습니다. Generative UI는 이 전제를 깨고, Agent가 맥락에 따라 필요한 화면을 즉석에서 생성합니다.

### 왜 필요한가 — "Chat Wall" 문제

에이전트 시스템은 텍스트 생성에는 탁월하지만 구조화된 입력이나 복잡한 출력이 필요할 때 "Chat Wall"이라는 한계에 부딪힌다. 예를 들어 레스토랑 예약을 처리하는 에이전트는 느리고 오류가 잦은 텍스트 교환으로 귀결된다. A2UI는 에이전트가 필요한 정확한 순간에 날짜 선택기, 시간 선택기, 제출 버튼이 있는 간단한 폼을 동적으로 생성하도록 하여 이를 해결한다. [DEV Community](https://dev.to/czmilo/the-a2ui-protocol-a-2026-complete-guide-to-agent-driven-interfaces-2l3c)

### 3가지 구현 패턴

대부분의 Generative UI 구현은 세 가지 패턴으로 나뉜다. 차이는 프론트엔드에 얼마나 많은 제어권이 남아 있는지, Agent에게 얼마나 많은 자유가 주어지는지다. (1) Static Generative UI: 프론트엔드가 UI를 소유하고 Agent는 미리 만들어진 컴포넌트 중 어떤 것을 보여줄지 선택하고 데이터를 채운다. (2) Declarative Generative UI: Agent가 구조화된 UI 명세(카드, 목록, 폼)를 반환하고 프론트엔드가 자체 제약과 스타일로 렌더링한다. (3) Open-ended Generative UI: Agent가 완전한 UI 표면을 반환한다. [DEV Community](https://dev.to/copilotkit/the-developers-guide-to-generative-ui-in-2026-1bh3)

### 실제 도입 현황

한 핀테크 고객사는 분석 대시보드에 6개의 별도 정적 보고서 뷰를 갖고 있었다. 6개의 화면, 각각 수작업으로 설계, 각각 별도의 유지보수 주기가 필요했다. 우리는 모두를 사용자의 역할, 최근 활동, 가장 자주 접근한 데이터를 기반으로 스스로를 재구성하는 단일 AI 기반 적응형 뷰로 대체했다. 지원 티켓이 27% 감소했다. [Stan](https://www.stan.vision/journal/ux-ui-trends-shaping-digital-products)

구글 내부에서 A2UI는 팀에게 Agent가 텍스트뿐만 아니라 풍부한 사용자 인터페이스를 생성하는 표준화된 방법을 제공한다. 이는 Gemini Enterprise에서 외부에 쉽게 노출될 수 있도록 내부적으로 구축된 Agent를 허용한다. [Google Developers](https://developers.googleblog.com/introducing-a2ui-an-open-project-for-agent-driven-interfaces/)

### UI 기획에 주는 시사점

Generative UI가 확산되면 "화면 설계"의 의미가 바뀝니다. 특정 화면을 설계하는 것이 아니라, Agent가 생성할 수 있는 **컴포넌트 카탈로그와 렌더링 규칙**을 설계하는 것이 됩니다. 브랜드 일관성·보안·접근성을 유지하는 책임은 여전히 설계자에게 있지만, 그 형태가 달라집니다.

## 진화 방향 ②. Ambient AI — Agent가 전용 화면 밖으로 나온다

### 개념

많은 agent-MCP 사용은 임베드된 에이전트를 통해 이루어질 것이다. 우리에게 요청하지 않아도 필요에 따라 다른 시스템에서 데이터를 가져오거나 내보내는 방식으로 워크플로우 안에 조용히 녹아들 것이다. [Substack](https://manialabs.substack.com/p/agentic-ux-and-design-patterns)

Ambient AI는 채팅창이나 별도 화면이 없는 AI입니다. 사용자가 기존 업무 환경(이메일, 슬랙, ERP)에서 일하는 동안 Agent가 백그라운드에서 맥락을 파악하고, 필요한 순간에만 출현합니다.

### 현재 구현 사례

**ServiceNow Now Assist:** 기존 Service Operations Workspace 화면에서 ✨ 아이콘 클릭 시 크기 조절 가능한 플로팅 패널로 출현. 전용 AI 화면 없음.

**Abridge (의료):** 의사가 환자와 대화하는 동안 백그라운드에서 녹음·분석. 의사가 별도로 아무것도 하지 않아도 진료 후 SOAP 노트 초안이 생성됨.

**Microsoft 365 Copilot:** 항상 켜진 에이전트 팀원이 업무 대화를 듣고(허가를 받고) 팀이 더 스마트하고 빠르게 일할 수 있도록 실시간으로 실행한다. [Salesforce](https://www.salesforce.com/uk/news/stories/the-future-of-ai-agents-top-predictions-trends-to-watch-in-2026/)

### UI가 사라지는 것이 아니라 역할이 바뀐다

인터페이스는 사라지지 않겠지만, 그 역할은 이동할 것이다. 일부 맥락에서 — 디지털 트윈 모니터링이나 제품 시나리오 비교처럼 — 시각화는 여전히 필수적이다. 인터페이스는 더 상황적이 될 것이다 — 인간의 인지, 감정, 또는 개입이 필요할 때만 나타난다. [Ey](https://www.studio.ey.com/en_gl/insights/how-agentic-AI-enables-a-new-approach-to-user-experience-design)

### UI 기획에 주는 시사점

Ambient AI 환경에서 UI 설계의 핵심 질문이 달라집니다. "어떤 화면을 만드는가"가 아니라 **"Agent가 언제, 어떻게 출현해야 하는가"**, 그리고 **"어떻게 사라져야 하는가"**. 너무 자주 출현하면 방해가 되고, 너무 조용하면 존재를 모릅니다. 이 등장/퇴장 타이밍이 Ambient AI UI 설계의 핵심 문제입니다.

## 진화 방향 ③. 자율성 거버넌스 UI — 감독이 제품 기능이 된다

### 개념

Agent가 더 많이, 더 오래 자율 실행할수록 **"무슨 일이 일어나고 있는지 파악하고 통제하는 것"** 자체가 독립된 UI 영역이 됩니다. 이것은 백엔드 모니터링 도구가 아니라 사용자 제품의 일부입니다.

자율성은 기술 시스템의 출력물이다. 신뢰성은 설계 프로세스의 출력물이다. 거버넌스와 책임의 매커니즘을 UI 수준에서 구현하는 것이 목표다. [Smashing Magazine](https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/)

### 실제 도입 현황

**ServiceNow AI Control Tower:** Agent 인벤토리·승인·성능 추적을 위한 별도 거버넌스 대시보드. 런타임 코파일럿 UI와 분리된 독립 화면.

**Cursor의 자율성 슬라이더:** "가장 좋은 LLM 애플리케이션은 자율성 슬라이더가 있다. 사용자가 AI에게 얼마나 많은 독립성을 줄지 제어한다. Cursor에서는 탭 자동완성, 특정 편집을 위한 Cmd+K, 또는 완전한 자율 에이전트 버전으로 실행할 수 있다." [Cursor](https://cursor.com/)

**Harvey AI Governance:** 로펌 전체 생산성 지표 가시성 + 권한 제어 + 감사 추적 내장.

### 거버넌스 UI의 3개 구성 화면

엔터프라이즈에서 거버넌스 UI는 세 화면으로 수렴하는 패턴이 보입니다.

|화면|역할|사용자|
|---|---|---|
|**런타임 코파일럿**|현재 진행 중인 Agent 작업 상호작용|실무자|
|**워크플로우 빌더**|Agent 워크플로우 정의·수정 (로우코드)|기획자/관리자|
|**컨트롤 타워**|Agent 전체 현황 모니터링, 성능 지표, 승인 관리|관리자/컴플라이언스|

2026년에 기업 에이전트는 대화형 인터페이스뿐만 아니라 비즈니스 프로세스 자동화 워크플로우, 비즈니스 애플리케이션, 데이터 애플리케이션을 통해서도 제공될 것으로 예상된다. [Acuvate software](https://acuvate.com/blog/2026-agentic-ai-expert-predictions/)

### UI 기획에 주는 시사점

거버넌스 UI를 "나중에 추가할 기능"으로 보면 실패합니다. Bain의 분석처럼 보안과 거버넌스는 레이어에 걸쳐 내재화되어야 하며, 배포 후 적용되는 것이 아니다. 제어 지점, 감사 가능성, 감독이 정상 운영의 일부가 된다. [Bain & Company](https://www.bain.com/insights/building-the-foundation-for-agentic-ai-technology-report-2025/) 즉 거버넌스 UI는 초기 설계부터 포함되어야 하는 핵심 구성요소입니다.

## 3대 진화 방향 요약

|방향|핵심 변화|UI 설계 단위의 변화|
|---|---|---|
|**Generative UI**|화면이 사전 설계 → 런타임 생성|개별 화면 → 컴포넌트 카탈로그 + 렌더링 규칙|
|**Ambient AI**|AI가 전용 화면 → 기존 환경에 임베드|화면 레이아웃 → 출현/퇴장 타이밍과 맥락|
|**자율성 거버넌스 UI**|감독이 백엔드 작업 → 제품 기능|단일 인터페이스 → 런타임 + 빌더 + 컨트롤 타워|
