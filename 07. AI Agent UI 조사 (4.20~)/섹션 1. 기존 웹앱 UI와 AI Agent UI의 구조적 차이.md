## 1. 기존 UI vs Agent UI — 무엇이 근본적으로 다른가?

기존 웹/앱 UI와 Agent UI의 차이는 **상호작용 모델의 패러다임 전환**에서 시작됩니다.

| 구분       | 기존 웹/앱 UI           | AI Agent UI                 |
| -------- | ------------------- | --------------------------- |
| 작동 방식    | 사용자가 요청하면 시스템이 반응   | Agent가 목표를 향해 **자율적으로 행동**  |
| 상호작용 단위  | 클릭/입력 → 즉각 응답 (단발성) | 목표 위임 → 다단계 실행 (장기 지속)      |
| 사용자 역할   | 조작자 (Navigator)     | 감독자 (Supervisor)            |
| 시스템 역할   | 수동적 실행기             | 능동적 실행자                     |
| 상태 모델    | 요청/응답 완결 후 종료       | 세션 간 상태 유지, 중간 작업 상태 존재     |
| UI 설계 대상 | 인간 사용자의 탐색 경로       | **인간 + Agent 모두**를 위한 인터페이스 |

기존 애플리케이션은 사용자가 명령할 때만 동작하는 반면, AI Agent는 능동적으로 행동을 수행한다. 이 행동들은 사용자를 압도하지 않으면서도 투명하게 전달되어야 한다.

기존 UI는 메뉴, 버튼, 미리 정의된 워크플로우 같은 정적 탐색 체계에 의존하며 사용자가 시스템을 명시적으로 지시해야 한다. 반면 AI Agent UI는 맥락 인식 상호작용, 능동적 보조, 인간 중심 기능을 제공한다.

챗봇 UX는 질의응답 대화다. 타이핑하면 봇이 응답하고 스레드가 스크롤된다. Agent UX는 근본적으로 다르다 — 도구, 시간, 시스템을 가로지르는 목표 추구다. 이는 상태 관리, 권한, 재시도, 감사 추적을 필요로 하는데, 이 중 어느 것도 채팅 창이 잘 처리하지 못한다.

## 핵심 질문 2. 챗봇 영역과 챗봇 외 영역은 왜 분리되는가?

Agent가 단순히 "대답"하는 게 아니라 **"실행"**하기 시작하면서, 대화창 하나로는 담을 수 없는 UI 요소들이 필연적으로 생겨납니다.

**챗봇 영역만으로 부족한 이유:**

- Agent는 장시간 실행되며 **중간 상태**가 존재함 → 진행 상황 표시 공간 필요
- 여러 도구를 호출하고 그 결과가 **구조화된 데이터**로 나옴 → 텍스트 외 렌더링 공간 필요
- 사용자가 언제든 **개입/중단/승인**할 수 있어야 함 → 컨트롤 패널 공간 필요
- 무슨 일이 일어났는지 **사후에도 확인** 가능해야 함 → 로그/히스토리 영역 필요

Agent는 장시간 실행되며 중간 작업을 스트리밍한다. Agent는 비결정적이며 애플리케이션 UI를 비결정적으로 제어할 수 있다. Agent는 텍스트와 음성, 도구 호출과 상태 업데이트 같은 구조화/비구조화 입출력을 동시에 혼합한다.

## 핵심 질문 3. 챗봇 영역 외에 어떤 UI 요소들이 등장하는가?

조사 결과 Agent 제품에서 반복적으로 등장하는 **챗 외 UI 구성요소**를 6가지로 분류할 수 있습니다.

### ① 상태/진행 표시 (Status & Progress)

Agent가 지금 무엇을 하고 있는지 실시간으로 보여주는 영역. 단순 로딩 스피너를 넘어 현재 실행 중인 스텝, 사용 중인 도구 이름, 예상 잔여 시간 등을 표시.

### ② 툴 사용 로그 / Thought Log (Transparency Panel)

Agent가 어떤 이유로 어떤 판단을 내렸는지 보여주는 영역. 가시적인 "thought log"나 Agent가 특정 행동 방침을 선택한 이유에 대한 계층적 설명 형태로 구현된다.

### ③ 승인/개입 컨트롤 (Human-in-the-Loop Surface)

Human-in-the-loop는 누군가가 Agent 오류를 Slack에서 모니터링하는 수동 영웅 워크플로우가 아니라, 설계된 에스컬레이션 경로를 갖춘 제품 UI여야 한다. 컨트롤 영역에는 자율성 수준 조절, 승인, 되돌리기/롤백, 안전 모드 폴백이 포함된다.

### ④ 액션 타임라인 / 감사 로그 (Activity Log)

Agent가 시작한 모든 액션의 시간 순 로그가 가장 직관적인 형태다. 액션의 성공 여부, 진행 중 여부, 취소 여부를 명확한 상태 표시로 보여줘야 한다.

### ⑤ 공유 상태/작업물 영역 (Shared State Panel)

Agent가 보고서 작성을 돕는 경우를 상상해보면, 단순히 대화하는 게 아니라 문서를 편집하고 있다. 사용자와 Agent가 동시에 타이핑할 수 있다. AG-UI는 이 문서를 공유 상태로 취급하며 서로 덮어쓰지 않도록 효율적인 업데이트로 화면과 Agent 메모리를 동기화한다.

### ⑥ 멀티 Agent 조율 대시보드 (Multi-Agent Dashboard)

여러 전문 Agent가 협력하는 경우, 어떤 Agent가 어떤 작업을 담당하는지 시각화하는 영역. 다수의 전문화된 AI Agent의 투명한 핸드오프, 협업 대시보드, Agent 간 원활한 컨텍스트 보존을 위한 UI가 필요하다.
