## AI Agent UI 조사 계획 초안

### 섹션 1. 기존 웹/앱 UI와 AI Agent UI의 구조적 차이

**왜:** 보고서 전체의 개념 기반. 독자(전무/상무님)가 "AI Agent UI가 왜 다른 문제인가"를 납득하게 하는 섹션.

**핵심 질문**

- 기존 UI는 사용자가 메뉴를 탐색하는 구조인데, Agent UI는 무엇이 다른가?
- 챗봇 영역 / 챗봇 외 영역의 구분이 왜 생기는가?
- 대화 외에 어떤 UI 요소들이 Agent 제품에 등장하는가? (상태 표시, 툴 사용 로그, 승인 버튼 등)

**조사 방법**

- 레퍼런스: Perplexity, Claude.ai, Cursor, Notion AI, GitHub Copilot Chat 등 직접 스크린샷 수집
- 문헌: "agentic UI patterns", "conversational UI vs agentic UI" 키워드로 UX 아티클 서치 (NN/g, UX Collective 등)

**난이도:** 낮음 — 개념 정리 + 사례 수집 위주

---

### 섹션 2. AI Agent 고도화에 따른 UI 진화 예측

**왜:** 경영진 관심 포인트. "지금 투자/설계해야 하는 이유"를 미래 방향으로 뒷받침.

**핵심 질문**

- Agent가 단순 챗 → 멀티스텝 작업 → 자율 실행으로 고도화될 때 UI는 어떻게 변해야 하는가?
- Human-in-the-loop의 정도에 따라 UI 컨트롤이 어떻게 달라지는가?

**조사 방법**

- Anthropic, OpenAI, Google 공개 자료 (Agent design principle 문서)
- Agent UI 관련 최신 아티클/컨퍼런스 발표 (2024~2025)
- 업계 동향 정리 → 숙진님이 기존에 정리한 "에이전트 패러다임 진화 매트릭스"와 연결 가능

**난이도:** 중간 — 예측 섹션이라 구조적 프레임이 필요

---

### 섹션 3. 도메인별 UI 구성 차이

**왜:** Sales Kit 활용도 가장 높은 섹션. "우리 고객사 도메인에 맞는 UI가 어떤 형태여야 하는가"로 연결.

**핵심 질문**

- 금융(Valley AI), 법률, 의료, 제조/품질, 코딩 보조 등 도메인별로 UI 구성이 어떻게 갈리는가?
- 챗봇이 메인인 경우 vs 대시보드가 메인인 경우 vs 워크플로우 임베드형은 어떤 기준으로 나뉘는가?

**조사 방법**

- Valley AI, Harvey (법률), Abridge (의료), Cursor (개발) 등 도메인별 레퍼런스 제품 스크린샷 + 구조 분석
- 제품 소개 영상/블로그 공식 자료 위주 (직접 가입 불필요)

**난이도:** 중간 — 사례 수집량이 관건

---

### 섹션 4. Agent UI 오픈소스 현황 및 커스터마이징 가능 영역

**왜:** AX TF팀 + 향후 개발 관점. "우리가 직접 만들 때 어디서 시작할 수 있는가."

**핵심 질문**

- 어떤 오픈소스 Agent UI 프레임워크가 있는가? (Chainlit, AG-UI, Open WebUI 등)
- 각각 커스터마이징 가능한 영역과 제약이 어디까지인가?
- 메타데이터 extractor 같은 도메인 특화 화면을 얹을 수 있는가?

**조사 방법**

- GitHub star/활동량 기준 주요 프레임워크 5~7개 선별
- 각 README + 데모 화면 + 라이선스 확인

**난이도:** 낮음~중간 — 조사는 쉽지만 정리 기준 잡기가 관건

---

### 섹션 5. Agent UI 페인포인트

**왜:** 차별화 포인트 섹션의 전제. "현재 무엇이 문제인가"를 먼저 설득해야 해결책이 설득됨.

**핵심 질문**

- 사용자 관점: 진행 상태 불투명, 결과 신뢰성 판단 어려움, 실수 복구 불가 등
- 개발자/기획자 관점: 대화 외 상태 관리 UI 부재, 멀티에이전트 시각화 어려움 등

**조사 방법**

- UX 커뮤니티 (Reddit r/ChatGPT, HN) 사용자 불만 수집
- 관련 아티클 ("AI agent UX problems", "chatbot UX frustration") 서치
- 내부 인터뷰 가능하면 추가 (AX TF팀 의견)

**난이도:** 낮음 — 유저 보이스 수집 위주

### 섹션 6. UI 전략 및 차별화 포인트

**왜:** 보고서의 결론이자 Sales Kit의 핵심 메시지.

**핵심 질문**

- S-Core가 Agent UI 설계에서 줄 수 있는 차별화된 가치는 무엇인가?
- "도메인 분석 → Agent 구조화 → UI 설계"로 이어지는 방법론을 어떻게 UI 전략으로 연결할 수 있는가?

**조사 방법**

- 앞 섹션 조사 결과를 종합해서 작성 (조사보다는 합성/작성 작업)
- S-Core Context Framework와의 연결 고리 명시

**난이도:** 높음 — 조사보다 기획/논리 작업

### 섹션 7. Use case별 UI 분류 — 설계 가이드 및 방법론

**왜:** 실무 활용도 가장 높은 섹션. AX TF팀이 실제 기획할 때 쓸 수 있는 가이드.

**핵심 질문**

- Use case 유형을 어떻게 분류할 것인가? (예: 정보조회형 / 문서생성형 / 프로세스자동화형 등)
- 각 유형별 권장 UI 패턴은 무엇인가?

**조사 방법**

- 앞 섹션의 도메인별 사례를 Use case 기준으로 재분류
- 설계 가이드 형식으로 정리 (표 + 예시 화면)

**난이도:** 높음 — 섹션 3, 4, 5 결과물에 의존
