# 섹션 6. UI 전략 및 차별화 포인트

## 왜 Agent UI 전략은 선형이 아닌가

기존 웹/앱 UI 전략은 "사용자 흐름을 설계하면 끝"입니다. 화면 A → 화면 B 경로를 잘 만들면 됩니다.

Agent UI는 다릅니다. Agent가 자율적으로 실행할수록 사용자와의 관계 자체가 설계 대상이 됩니다.

자율성은 기술 시스템의 출력물이다. 신뢰성은 설계 프로세스의 출력물이다.

전통적인 UX 설계는 단순한 모델을 가정했다. 사용자가 시작하고, 시스템이 반응한다. Agentic AI는 이 입력-반응 루프를 위임으로 대체한다. 사용자는 이제 명령이 아닌 의도를 표현한다. 시스템이 단계를 결정하고, 도구를 선택하고, 데이터를 수집하고, 행동을 실행한다.

이 위임 관계는 한 번 설계하면 끝나는 것이 아닙니다. 사용자가 Agent를 더 많이 써볼수록, 신뢰가 쌓일수록 관계가 달라지기 때문입니다.

---

## 신뢰는 고정값이 아니라 누적값이다

Anthropic의 Claude Code 실사용 데이터가 이 비선형성을 가장 명확하게 보여줍니다.

사람들이 경험이 쌓일수록 Claude Code에 더 많은 자율성을 부여하는 것을 발견했다. 50회 미만 세션의 신규 사용자는 약 20%의 시간 동안 전체 자동 승인을 사용한다. 750회 세션이 되면 이 수치는 40% 이상으로 증가한다. 이 변화는 점진적이며, 신뢰의 꾸준한 누적을 시사한다.

이 데이터가 말하는 것: 사용자는 처음부터 Agent를 신뢰하지 않습니다. **신뢰는 반복된 상호작용을 통해 점진적으로 누적됩니다.** UI 전략은 이 누적 과정을 지원하도록 설계되어야 합니다.

|사용 단계|신뢰 수준|UI가 해야 할 일|
|---|---|---|
|초기 (0~50회)|낮음, 관찰 중|투명성 최대화, 모든 액션에 확인 요청|
|중기 (50~300회)|쌓이는 중|반복 작업은 자동화 시작, 예외만 개입 요청|
|성숙기 (300회+)|높음|자율 실행 기본, 감사 로그로 사후 검증|

따라서 "어느 수준의 자율성을 주는가"는 제품 설계 시 단일 답을 내리는 문제가 아닙니다. 사용자의 신뢰 누적 단계에 맞게 **자율성이 조정될 수 있는 구조**를 처음부터 설계해야 합니다.

## 상호작용 라이프사이클 — Agent UI의 핵심 설계 단위

Agent UI에서 설계해야 할 단위는 "화면"이 아니라 **한 번의 Agent 실행 사이클**입니다. Smashing Magazine이 정리한 가장 실용적인 프레임워크입니다.

아젠틱 인터랙션의 기능적 라이프사이클에 따른 6가지 패턴: 사전 행동(Pre-Action)에서 의도 미리보기와 자율성 다이얼이 의도를 수립한다. 행동 중(During-Action)에는 투명성이 유지되고, 사후 행동(Post-Action)에는 영수증, 취소, 설명적 근거가 뒤따른다.

**단계 1 — Pre-Action: 의도 명확화**

- Agent가 실행하기 전에 "이렇게 이해했습니다, 맞습니까?"를 보여주는 Intent Preview
- 이번 작업에 대한 자율성 수준을 조절하는 Autonomy Dial
- 고위험 작업에서 실행 전 플랜 검토 허용

**단계 2 — During-Action: 실행 투명성**

- Agent가 지금 무엇을 하고 있는지 실시간 상태 표시
- 사용 중인 툴, 접근 중인 데이터 표시
- 언제든 개입·중단 가능한 컨트롤 유지

**단계 3 — Post-Action: 행동 영수증**

- 무엇이 변경되었는지, 어디서, 언제, 어떤 Agent가
- Undo 가능한 시간 창 명시
- "왜 이 결정을 했는가" 설명적 근거 제공

영구적이고 읽기 쉬운 액션 감사 로그와 모든 가능한 액션에 대한 눈에 띄는 Undo 버튼은 궁극적인 안전망이다. 자율성 부여의 인지된 위험을 크게 낮춘다. 실수를 쉽게 되돌릴 수 있다는 것을 알면 심리적 안전감이 생기고, 사용자들이 돌이킬 수 없는 결과에 대한 두려움 없이 작업을 위임하도록 장려한다.

이 Pre-Action → During-Action → Post-Action 사이클은 **매 Agent 실행마다 반복**됩니다. 이것이 선형 설계가 작동하지 않는 이유입니다. 화면을 한 번 만드는 게 아니라 이 반복 사이클을 얼마나 잘 설계하느냐가 전략의 핵심입니다.

## 차별화 포인트 — 무엇이 Agent UI를 실제로 다르게 만드는가

조사 결과를 종합하면 Agent UI의 실질적인 차별화 요인은 3가지로 정리됩니다.

### ① 신뢰 설계의 깊이

AI는 성능만으로 신뢰를 얻지 않는다. 가시성을 통해 신뢰를 얻는다. 그리고 가시성은 책임 있는 자율성의 토대다.

표면적인 채팅 UI와 신뢰 있는 Agent UI의 차이는 "얼마나 잘 보이는가"에 있습니다. 신뢰 설계를 표피적으로(로딩 스피너, "처리 중..." 메시지) 처리하는 제품과, 추론 근거·출처·행동 영수증까지 설계하는 제품 사이에는 큰 격차가 있습니다.

### ② 자율성의 조절 가능성

슬라이더 또는 모드 선택기를 통해 사용자(또는 관리자)가 워크플로우나 위험 등급별로 에이전트의 자율성을 설정할 수 있다. 처음 실행하는 워크플로우에는 낮은 자율성을 기본으로 설정하고, 에이전트가 입증된 신뢰성을 통해 자율성을 얻도록 한다.

사용자가 Agent의 자율성 수준을 직접 조절할 수 있느냐 없느냐는 단순한 기능 차이가 아닙니다. 사용자가 제어권을 가진다고 느끼느냐 빼앗겼다고 느끼느냐의 심리적 차이입니다.

### ③ 거버넌스의 설계 내재화 여부

진정한 에이전트 프로세스 자동화는 의도, 컨텍스트, 오케스트레이션, 지식이라는 인텔리전스 레이어가 필요하다. 채팅 기반 UI가 편의성을 제공할 수 있지만, 레거시 앱에 챗봇 인터페이스를 덧씌우는 것은 오케스트레이션, 컨텍스트, 지식 통합의 더 깊은 문제를 해결하지 못한다.

감사 로그, 권한 관리, 에스컬레이션 경로를 배포 후 덧붙이는 제품과, 설계 초기부터 내재화한 제품의 차이가 2026년의 실질적 경쟁력이 되고 있습니다.

## 전략 선택 — Agent-native vs. Legacy-embedded

3번째 티어의 신생 기업들은 기존 소프트웨어 패러다임을 완전히 우회하며, 자율 에이전트가 보조 기능이 아닌 주요 인터페이스인 경험을 설계한다. 이들은 레거시 코드베이스, 기존 UI 패턴, 또는 기존 워크플로우에 제약받지 않아 다른 가치 제안이 가능하다.

현재 시장에는 두 가지 전략 경로가 명확하게 갈리고 있습니다.

|전략|정의|장점|단점|
|---|---|---|---|
|**Agent-native**|Agent가 주인터페이스, 기존 UI 관습 없음|최적 설계 가능, 미래 지향|사용자 학습 비용 높음, 신뢰 축적 시간 필요|
|**Legacy-embedded**|기존 도구(ERP, CRM, IDE) 안에 Agent 삽입|기존 사용자 습관 활용, 빠른 채택|기존 UI 제약에 묶임, 거버넌스 후처리 위험|

어느 경로가 맞는지는 "사용자가 이미 어디서 일하는가"와 "Agent 실행의 위험도가 얼마나 높은가"에 달려 있습니다.
