
## 먼저 구분해야 할 두 레이어

Agent UI 오픈소스 생태계를 이해하려면 **프레임워크 레이어(화면을 만드는 도구)**와 **프로토콜 레이어(Agent와 UI가 통신하는 방식)** 두 가지를 분리해서 봐야 합니다.

기존 섹션에서 이 둘을 같은 수준으로 나열했는데, 실제로는 프로토콜 레이어가 더 근본적입니다. 어떤 프레임워크를 쓰든 이 프로토콜 위에서 작동하는 방향으로 생태계가 빠르게 수렴하고 있기 때문입니다.

---

## 프로토콜 레이어 — 3개 프로토콜이 하나의 스택을 형성

2025~2026년에 걸쳐 Agent 통신 표준이 3개 프로토콜로 정리되고 있습니다. 각각 다른 계층을 담당합니다.

AG-UI는 MCP와 A2A를 완성하는 마지막 조각으로, 백엔드 AI Agent와 프론트엔드 사용자 인터페이스를 명시적으로 연결하는 첫 번째 프로토콜이다. MCP는 도구를, A2A는 에이전트 협업을, AG-UI는 사용자 상호작용을 각각 담당하는 현대 AI 애플리케이션의 근간을 형성한다. [GUVI](https://www.guvi.in/blog/how-the-agent-user-interaction-protocol-works/)

|프로토콜|담당 계층|만든 곳|역할|
|---|---|---|---|
|**MCP**|Agent ↔ 도구/데이터|Anthropic|Agent가 외부 툴·DB에 연결하는 방법 표준화|
|**A2A**|Agent ↔ Agent|Google|서로 다른 Agent 간 협업·통신 표준화|
|**AG-UI**|Agent ↔ 프론트엔드 UI|CopilotKit|Agent 실행 상태를 UI에 실시간 전달하는 방법 표준화|

이 세 프로토콜은 경쟁이 아니라 보완 관계입니다. 실제 엔터프라이즈 Agent 시스템은 세 가지를 모두 씁니다.

## AG-UI 상세 — "파이프(Pipe)"

### 무엇을 해결하는가

기존에는 Agent 백엔드와 프론트엔드를 연결하려면 각 Agent 프레임워크(LangGraph, CrewAI 등)마다 별도의 커스텀 WebSocket 코드를 작성해야 했습니다.

AG-UI는 에이전트 백엔드와 프론트엔드 앱 사이의 공통 언어를 제거하여 모든 에이전트 백엔드가 사용자 인터페이스와 통신하기 위해 커스텀 통합 코드가 필요 없도록 한다. AG-UI는 에이전트가 작동하는 동안 업데이트를 스트리밍하는 이벤트 기반 아키텍처를 채택한다. [Codecademy](https://www.codecademy.com/article/ag-ui-agent-user-interaction-protocol)

### 작동 방식

AG-UI는 프론트엔드 애플리케이션과 AI Agent 간의 원활하고 효율적인 통신을 가능하게 하는 유연한 이벤트 기반 아키텍처를 기반으로 한다. 이벤트 기반 통신: Agent는 실행 중에 16가지 표준화된 이벤트 타입 중 하나를 방출해야 하며, 클라이언트가 처리할 수 있는 업데이트 스트림을 생성한다. 양방향 상호작용: Agent는 사용자로부터 입력을 받아 인간과 AI가 원활하게 협력하는 워크플로우를 가능하게 한다. [Ag-ui](https://docs.ag-ui.com/concepts/architecture)

### 16가지 이벤트 타입 — UI와의 실질적 연결

프로토콜은 Server-Sent Events(SSE)를 통해 각 이벤트가 무슨 일이 일어나고 있는지 프론트엔드에 알려주는 type 필드를 가진 JSON 객체를 사용한다. 라이프사이클 이벤트(RUN_STARTED, RUN_FINISHED, RUN_ERROR)는 Agent가 언제 작업을 시작하고 끝내는지 신호를 보낸다. 텍스트 메시지 이벤트(TEXT_MESSAGE_START, TEXT_MESSAGE_CONTENT, TEXT_MESSAGE_END)는 텍스트를 토큰 단위로 스트리밍한다. 툴 콜 이벤트(TOOL_CALL_START, TOOL_CALL_ARGS, TOOL_CALL_RESULT, TOOL_CALL_END)는 툴 활동을 실시간으로 보고한다. 상태 이벤트(STATE_SNAPSHOT, STATE_DELTA)는 백엔드와 프론트엔드 간의 공유 상태를 동기화한다. [Ag2](https://docs.ag2.ai/latest/docs/blog/2026/02/17/AG2-AG-UI-Protocol/)

이 이벤트 타입들이 섹션 1에서 정의한 6개 UI 컴포넌트를 실제로 작동시키는 기술 기반입니다.

|이벤트 타입|UI에서 보이는 것|
|---|---|
|`RUN_STARTED / RUN_FINISHED`|상태 표시 바 (실행 중 / 완료)|
|`TOOL_CALL_START / TOOL_CALL_RESULT`|툴 사용 로그, Thought Log|
|`STATE_DELTA`|공유 작업물 영역 실시간 업데이트|
|`TEXT_MESSAGE_CONTENT`|채팅 영역 토큰 스트리밍|
|`RUN_ERROR`|오류 상태 + 복구 안내|

### 생태계 현황

AG-UI는 GitHub에서 9,000개 이상의 별을 받았으며, 공간에서 가장 빠르게 성장하는 오픈소스 프로토콜 프로젝트 중 하나다. AG-UI와 CopilotKit은 주당 12만 건의 설치를 기록했다. Google의 ADK가 공식적으로 AG-UI 생태계에 합류했다. [CopilotKit](https://www.copilotkit.ai/blog/ag-ui-is-redefining-the-agent-user-interaction-layer)

지원 프레임워크: LangGraph, CrewAI, Mastra, AG2, Google ADK, AWS Bedrock Agents, Vercel AI SDK 등 주요 Agent 프레임워크 대부분이 통합 중이거나 완료.

## A2UI 상세 — "콘텐츠(Content)"

### AG-UI와의 근본적 차이

A2UI는 선언적 생성형 UI 명세다. Agent가 사용자에게 UI를 보여주고 싶을 때, HTML이나 JavaScript를 출력하는 것이 아니라 A2UI 응답을 출력한다. 컴포넌트, 속성, 데이터 모델을 설명하는 JSON 페이로드. 클라이언트 애플리케이션은 이 설명을 읽고 각 컴포넌트를 자체 네이티브 위젯에 매핑한다. [A2ui](https://a2ui.sh/articles/a2ui-vs-ag-ui)

한 문장으로: **AG-UI는 파이프, A2UI는 파이프를 통해 흐르는 콘텐츠**입니다.

A2UI는 무엇을 렌더링할지를 정의한다. AG-UI는 UI와 그 외 모든 것이 백엔드와 프론트엔드 사이에서 어떻게 흐르는지를 정의한다. 함께 쓰는 방법: AG-UI를 파이프로, A2UI를 콘텐츠로 사용한다. [A2ui](https://a2ui.org/introduction/agent-ui-ecosystem/)

### A2UI가 해결하는 문제

멀티 Agent 환경에서 원격 Agent(다른 서버, 다른 조직)가 UI를 렌더링해야 할 때 기존에는 두 가지 방법밖에 없었습니다. HTML/JavaScript를 보내면 보안 문제, iframe으로 샌드박스하면 앱과 시각적으로 이질적. A2UI는 세 번째 경로를 만듭니다.

클라이언트 애플리케이션은 자체 네이티브 UI 컴포넌트를 사용해 렌더링한다. 이는 클라이언트가 스타일링과 보안에 대한 완전한 제어권을 유지하도록 하여, Agent의 출력이 앱에 항상 네이티브하게 느껴지도록 돕는다. [Google Developers](https://developers.googleblog.com/introducing-a2ui-an-open-project-for-agent-driven-interfaces/)

### 보안 우선 설계

보안 우선: 선언적 데이터 형식이지, 실행 가능한 코드가 아니다. 클라이언트는 신뢰할 수 있는 컴포넌트 카탈로그(Card, Button, TextField)를 유지한다. Agent는 이 카탈로그의 타입만 참조할 수 있으며, 임의의 스크립트를 실행할 수 없다. [A2ui](https://a2ui.sh/articles/a2ui-vs-ag-ui)

### 실제 활용 예시

한 개발자는 AI 쇼핑 에이전트에 커스텀 React 렌더러를 구현했다. 에이전트가 사용자 의도에 따라 UI를 동적으로 전환한다. "제품 검색" 의도는 비교 테이블을 렌더링하고, "DIY 프로젝트" 의도는 인터랙티브 타임라인/체크리스트를 렌더링한다. [DEV Community](https://dev.to/czmilo/the-a2ui-protocol-a-2026-complete-guide-to-agent-driven-interfaces-2l3c)

## AG-UI + A2UI 조합 구조

```
[사용자]
   ↕ (AG-UI: 실시간 이벤트 스트림)
[프론트엔드 앱]
   ↕ (A2UI JSON 페이로드 렌더링)
[Agent 백엔드]
   ↕ (MCP: 툴/데이터 연결)
[외부 데이터/API]

[Agent 백엔드]
   ↕ (A2A: Agent 간 협업)
[다른 Agent 백엔드]
```

## 프레임워크 레이어 — 실제 화면을 만드는 도구

프로토콜 위에서 작동하는 SDK 레이어입니다. 저자유도 도구(Streamlit, Gradio)는 Agent UI 프로덕션 용도에 적합하지 않아 제외합니다.

### CopilotKit

**성격:** React/Next.js 앱에 AG-UI 기반 Agent 기능을 임베드하는 풀스택 SDK

CopilotKit은 인앱 코파일럿을 위한 에이전트 프레임워크로 20,000개 이상의 GitHub 별과 100,000명 이상의 개발자가 신뢰한다. AG-UI 자체가 CopilotKit에서 표준 레이어로 이동했으며, 모든 Agent-UI 통신이 백엔드별 커스텀 연결 대신 단일 이벤트 스트림이 된다. [MarkTechPost](https://www.marktechpost.com/2025/12/11/copilotkit-v1-50-brings-ag-ui-agents-directly-into-your-app-with-the-new-useagent-hook/)

- **제공 기능:** Chat UI (스트리밍), Generative UI, Shared State, HITL(실행 일시 중지 + 사용자 확인 요청)
- **커스터마이징:** 컴포넌트 완전 교체 가능, 도메인 전용 UI 패널 추가 용이
- **A2UI 지원:** Google의 공식 A2UI 런치 파트너로 완전 통합

### Open WebUI

**성격:** 로컬 LLM 및 외부 API를 연결하는 Self-hosted 웹 채팅 인터페이스

- **강점:** 완전한 셀프호스팅, 기업 내부 보안 환경 적합, MCP 서버 연동 지원
- **커스터마이징:** 화이트라벨링, SSO, 워크스페이스 분리
- **GitHub 별점:** 90,000+ (가장 활발한 오픈소스 Agent UI 중 하나)

## 최종 비교 — 어떤 경우에 무엇을 선택하는가

|상황|권장 선택|
|---|---|
|React 앱에 Agent 기능 추가, HITL 필요|CopilotKit + AG-UI|
|기존 앱 없이 Agent가 UI를 동적 생성해야 함|A2UI + AG-UI|
|보안 환경, 셀프호스팅, 채팅 중심|Open WebUI|
|데모·프로토타입 빠르게 (프로덕션 아님)|Gradio / Streamlit (단기만)|
|멀티 Agent, 크로스 플랫폼 UI|A2UI + A2A + AG-UI 조합|
