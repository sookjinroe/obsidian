오픈소스 Agent UI 생태계는 크게 **프레임워크 레이어**와 **프로토콜 레이어** 두 축으로 구분됩니다. 프레임워크는 "UI를 어떻게 만드는가", 프로토콜은 "Agent와 UI가 어떻게 통신하는가"를 다룹니다.

---

## UI 프레임워크 (직접 화면을 만드는 도구)

### Chainlit

**성격:** Python 기반 대화형 AI 앱 전용 채팅 UI 프레임워크

Chainlit은 채팅 UI, 인증, 관찰 가능성 등 운영에 필요한 세부 사항을 처리하므로 개발자가 인터페이스 코드 대신 Agent 로직에 집중할 수 있다. 내장된 관찰 가능성 기능으로 "데이터베이스 검색 사용", "사용자 의도 분석 중" 같은 중간 단계를 자동으로 시각화한다.

- **강점:** 빠른 초기 셋업, 툴 사용 로그 자동 시각화, SSO 인증 내장
- **커스터마이징 가능 영역:** 테마/CSS, 채팅 컴포넌트 스타일, 브랜딩
- **제약:** 채팅 UI 외 대시보드·워크플로우 빌더 등 챗 外 화면 구성 어려움
- **주의:** 2025년 5월부터 원 개발팀이 물러나 커뮤니티 유지보수 체제로 전환됨
- **GitHub 별점:** ~8,000+

---

### CopilotKit

**성격:** React/Next.js 기반 앱에 AI Copilot을 임베드하는 프론트엔드 SDK

CopilotKit은 Chat UI(메시지 스트리밍, 툴 콜, Agent 응답 지원), 백엔드 툴 렌더링(Agent가 UI 컴포넌트를 반환), Generative UI(Agent가 런타임에 UI 컴포넌트를 동적으로 생성), Shared State(Agent와 UI 컴포넌트가 실시간 공유 상태 읽기/쓰기), Human-in-the-Loop(Agent가 사용자 입력·확인·편집을 요청하며 실행 일시 중지) 기능을 제공한다.

- **강점:** 기존 React 앱에 Agent 기능을 추가하는 데 최적화, AG-UI 프로토콜의 창시자
- **커스터마이징 가능 영역:** 컴포넌트 완전 교체 가능, 도메인 전용 UI 패널 추가 용이
- **GitHub 별점:** 20,000+ 별, 10만 명 이상의 개발자가 사용 중

---

### Streamlit / Gradio

**성격:** 빠른 프로토타이핑 및 데모용 Python UI 프레임워크

Gradio는 빠른 데모와 내부 이해관계자 시연에 최적화되어 있다. 5줄의 코드와 즉시 사용 가능한 공개 링크로 실험과 프로토타이핑에는 적합하지만, 프로덕션 환경에는 적합하지 않다.

- **강점:** AX TF 데모 화면 빠르게 시각화할 때 활용 가능
- **제약:** 프로덕션 수준의 커스터마이징 한계, 엔터프라이즈 인증 지원 약함

---

### Open WebUI

**성격:** 로컬 LLM과 외부 API를 연결하는 Self-hosted 웹 채팅 인터페이스

- **강점:** 완전한 셀프호스팅, 기업 내부 보안 환경에 적합, MCP 서버 연동 지원
- **커스터마이징 가능 영역:** 화이트라벨링, SSO, 워크스페이스 분리
- **GitHub 별점:** 90,000+ (가장 활발한 오픈소스 Agent UI 프로젝트 중 하나)

## 프로토콜 레이어 (Agent ↔ UI 통신 표준)

프레임워크보다 더 중요하게 떠오르는 레이어입니다. 어떤 프레임워크를 쓰더라도 이 프로토콜 위에서 작동하게 되는 방향으로 생태계가 수렴 중입니다.

### AG-UI (Agent-User Interaction Protocol)

CopilotKit이 만들고 Google, AWS, Microsoft 등이 채택하고 있는 Agent ↔ 프론트엔드 실시간 통신 표준입니다.

AG-UI와 CopilotKit은 주당 12만 건의 설치 수를 기록하며 빠르게 채택되고 있다. Google의 ADK가 공식적으로 AG-UI 생태계에 합류해 통합을 출시했고, Oracle, Google, CopilotKit이 공동으로 세 레이어를 표준화하는 통합을 발표했다.

**16가지 이벤트 타입으로 Agent 상태를 UI에 전달:**

- `TEXT_MESSAGE_CONTENT` → 토큰 스트리밍
- `TOOL_CALL_START` → 툴 실행 시각화
- `STATE_DELTA` → 공유 상태(코드, 데이터) 동기화
- `AGENT_HANDOFF` → Agent 간 제어 전환

### A2UI (Agent-to-UI, by Google)

Agent가 UI 컴포넌트 자체를 JSON으로 생성·전송하면 프론트엔드가 네이티브 렌더링하는 방식입니다.

Generative UI는 개발자가 모든 버튼, 폼, 패널을 미리 하드코딩하는 대신 사용자의 필요와 컨텍스트에 따라 UI가 동적으로 생성되는 패턴이다. Agent는 어떤 UI를 보여줄지, 사용자로부터 어떤 입력이 필요한지, 작업이 진행됨에 따라 상태를 어떻게 업데이트할지 결정할 수 있다.

## Generative UI 3가지 패턴과 커스터마이징 수준

Controlled Generative UI(높은 제어, 낮은 자유도)는 프론트엔드가 UI를 소유하고 Agent는 어떤 컴포넌트를 보여줄지 선택하고 데이터를 채운다. Declarative Generative UI(공유 제어)는 Agent가 구조화된 UI 설명(카드, 목록, 폼, 위젯)을 반환하고 프론트엔드가 이를 렌더링한다. Open-ended Generative UI(낮은 제어, 높은 자유도)는 Agent가 HTML/SVG 등 완전한 UI를 생성한다.

|패턴|제어 주체|커스터마이징 난이도|도메인 특화 가능성|
|---|---|---|---|
|Controlled|프론트엔드|낮음|매우 높음|
|Declarative|Agent + 프론트엔드 공유|중간|높음|
|Open-ended|Agent|높음|중간|

## S-Core 관점 — 메타데이터 Extractor 화면과의 연결

이번 조사에서 도메인 특화 UI를 구현할 때 가장 현실적인 경로는 다음과 같습니다.

```
CopilotKit (React SDK, AG-UI 기반)
  └─ 채팅 영역 : 기본 제공 컴포넌트 활용
  └─ 메타데이터 추출 결과 패널 : 커스텀 컴포넌트로 추가
  └─ Human-in-the-Loop 승인 UI : 내장 기능 활용
  └─ 추출 이력/감사 로그 : Shared State 연동

데모/프로토타입 단계 → Streamlit or Gradio (빠른 시각화)
프로덕션 단계 → CopilotKit + AG-UI 기반으로 전환
```
