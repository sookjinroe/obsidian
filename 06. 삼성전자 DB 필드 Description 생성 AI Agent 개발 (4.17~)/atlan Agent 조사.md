## 1. raw metadata를 읽어 기본적인 컨텍스트를 구축하는 에이전트
### Scout - Usage & Query Intelligence
목적: 사용량 분석을 통해 자산 순위를 매겨 팀에서 가장 많이 검색하는 항목을 보여주는 에이전트
컨텍스트가 필요한 가장 중요한 자산을 찾아냅니다. 쿼리 기록과 접근 패턴을 분석하여 사용자가 실제로 사용하는 자산에 대한 정보 보강을 목표로 합니다.
1. 모든 팀과 사용 사례에 걸쳐SQL 쿼리 기록을 스캔
2. 팀, 빈도 및 기능별가장 많이 조회된 자산을 파악
3. 사용 점수별 순위 그리고 증강 우선순위를 지정

### Scribe - Description Agent
목적: SQL 패턴, 열 이름 및 계보를 기반으로 정확한 설명을 작성하는 에이전트
면밀한 검토에도 타당성을 유지하는 설명을 작성합니다. SQL 사용 패턴, 컬럼 이름 및 리니지 정보를 분석하여 모든 테이블과 열에 대한 정확한 설명을 생성합니다. + 신뢰도 생성

### Lexis - Glossary Bootstrapping
목적: 카탈로그의 열 이름 지정 패턴을 기반으로 비즈니스 용어집을 구축합니다.
귀사의 비즈니스 용어집은 수년 동안 "Comming soon"이라는 상태로 남아 있었습니다. Lexis는 기존 정의, 열 이름 지정 규칙 및 도메인 패턴을 기반으로 용어집을 구축합니다.
1. 카탈로그 전체의 열 이름 지정 패턴을 스캔
2. 도메인 컨벤션과 기존 정의를 읽기
3. 시그널 소스별로 그룹화된 용어를 추출하고 정의를 작성
4. 재무 · 제품 · 고객 성공 등 도메인별로 정리

## 2. 기초적인 맥락 정보를 구조화된 비즈니스 지식으로 종합하는 에이전트(추출)
### Doc - Readme Agent
목적: 흩어진 시그널들을 팀에서 작성하지 않았던 README 데이터셋으로 변환하는 에이전트
흩어진 시그널들을 팀에서 활용할 수 있는 문서로 변환합니다. 설명, 사용 시그널, 데이터 리니지 등을 종합적인 데이터셋 문서로 만들어 줍니다.
예시

|**항목**|**내용 (에이전트 산출물)**|**분석 근거 (Source Signals)**|
|---|---|---|
|**Overview**|매출(ARR)을 고객 세그먼트와 계약 시작일별로 추적하는 용도임.|**Scribe의 설명 + 테이블 명명 규칙:** `Scribe`가 생성한 컬럼별 정의와 `arr_cohort`라는 테이블 물리 명칭의 세부 의미(Semantics)를 결합하여 목적을 추론함.|
|**Lineage**|`billing.subscriptions`에서 데이터를 받아 `revenue_dashboard`로 보냄.|**Enterprise Data Graph:** SQL 파싱(Parsing) 결과와 ETL 파이프라인 메타데이터를 통해 확인된 상하위(Upstream/Downstream) 연결 관계를 참조함.|
|**Key Columns**|이 테이블에서 가장 중요한 건 `cohort_month`, `arr_usd` 컬럼임.|**Scout의 컬럼별 사용 통계:** 전체 쿼리 중 해당 컬럼이 `SELECT`, `WHERE`, `GROUP BY` 절에 사용된 빈도와 중요도 점수를 기반으로 추출함.|
|**Usage**|지난 30일간 284번 조회됨. 주로 '매출 분석 팀'이 사용함.|**SQL Audit Logs + 조직도:** 데이터 웨어하우스(Snowflake, BigQuery 등)의 쿼리 실행 로그와 사용자 계정의 부서 정보(SSO/LDAP)를 교차 분석함.|

### Nexus - Terms & Metrics Linkage
목적: 각 컬럼 이름을 분석가들이 실제로 사용하는 비즈니스 용어와 연결합니다.
코드와 대화 사이의 간극을 좁혀줍니다. 기술적인 컬럼 이름과 분석가들이 실제로 사용하는 비즈니스 용어를 연결해 줍니다.
1. 스키마에서 컬럼 이름을 읽기
2. 용어집 용어와 대조
3. 각 매핑에 대한 신뢰도 점수 부여
4. 신뢰도가 낮은 매핑은 검토를 위해 에스컬레이션

### Sage - Metric Confilcts
목적: 두 팀이 동일한 지표를 다르게 정의하는 부분을 찾아내고, 하나의 정답을 확정하는 에이전트
두 팀이 동일한 지표를 다르게 정의하는 부분을 찾아내고, 하나의 정답을 확정합니다. 충돌을 파악하고, 팀 담당자에게 전달하며, 승인되면 정의를 업데이트합니다.
1. 카탈로그에서 지표 이름과 계산 로직(SQL, BI 수식)을 스캔
2. 이름은 같지만 수식이나 필터 조건이 다른 '지표 충돌' 사례를 식별
3. 각 부서의 데이터 책임자(Steward)에게 충돌 내역을 보고하고 검토 요청
4. 담당자 합의 및 승인 시, 공인된 단일 정의로 잠금(Lock) 및 카탈로그 업데이트


## 3. 고도의 기업용 인텔리전스를 구축하는 에이전트.
### Atlas - Domain Tagging
목적: 모든 자산에 비즈니스 도메인 태그를 자동으로 대규모로 지정합니다.
모든 자산을 전사 데이터 체계 내 적정 위치에 매핑합니다. 각 자산을 올바른 비즈니스 도메인으로 분류함으로써, AI 에이전트가 사용자 정보에 기반해 최적의 컨텍스트를 식별할 수 있도록 지원합니다.
1. Scribe 설명 및 사용 신호를 읽기
2. 자산 메타데이터와 사전 정의된 비즈니스 도메인 패턴과 대조
3. 각 자산에 대한 도메인 적합성 점수 산출
4. 도메인 태그를 자동 적용하거나, 판단이 모호한 경우 담당자(Steward)에게 검토 요청


### Vera - Data Quality
목적: 데이터의 완전성, 정확성, 최신성 등 모든 핵심 요소별 데이터 품질을 평가하는 에이전트
AI가 신뢰할 수 있는 자산과 신뢰할 수 없는 자산을 구분하는 데 도움을 줍니다. 핵심 자산의 완전성, 정확성, 최신성을 자동으로 평가합니다.
1. 리니지를 분석하여 Downstream에 의존성이 많은 중요 에셋을 우선적으로 선별
2. 완전성, 정확성, 최신성 검사
3. 종합 품질 점수 산출
4. 점수에 따라 자동 조치 또는 담당 관리자(steward)에게 라우팅

### Orion - Ontology
목적: 모든 용어가 모든 맥락에서 어떤 의미를 갖는지 보여주는 에이전트
모든 용어가 모든 맥락에서 어떤 의미를 갖는지 매핑합니다. 도메인, 용어 및 자산 간의 모든 관계를 매핑하여 상담원이 "수익"이 무엇을 의미하는지 물어볼 때 적절한 맥락에 맞는 정확한 답변을 얻을 수 있도록 합니다.
- 용어, 지표, 도메인 등 파편화된 메타데이터를 지식 그래프로 연결
- 데이터 간의 입체적인 비즈니스 관계망을 구축
- AI 에이전트가 데이터 간 경로를 추적하며 복합 질문에 대해 정교하게 추론
- 사용자 도메인에 최적화된 맥락을 제공하여 답변의 일관성과 신뢰도를 보장

## 시그널
### 1. 사용 시그널 (Usage Signals)
데이터가 **'실제로 어떻게 소비되는가'**에 대한 신호입니다.
- **Query Logs:** 누가, 어떤 SQL 쿼리를, 얼마나 자주 날렸는지에 대한 기록.
- **Access Patterns:** 특정 테이블이 어떤 대시보드(BI)나 애플리케이션에 연결되어 있는지.
- **User Behavior:** 어떤 데이터가 가장 많이 조회되고, 어떤 필터(Where 절)가 가장 자주 사용되는지.
- **에이전트 활용:** `Scout`이 이 신호를 읽어 자산의 중요도와 우선순위를 판단합니다.
    

### 2. 계보 시그널 (Lineage Signals)
데이터가 **'어디서 와서 어디로 가는가'**에 대한 신호입니다.
- **Upstream/Downstream:** 원천 소스 테이블부터 최종 리포트까지의 연결 고리.
- **Transformation Logic:** ETL 과정에서 데이터가 어떻게 변환(Join, Aggregation)되었는지 보여주는 SQL 코드.
- **에이전트 활용:** `Scribe`와 `Doc`이 이 신호를 통해 데이터의 출처와 영향도를 파악하여 설명을 작성합니다.
    

### 3. 구조 및 명명 시그널 (Structural & Naming Signals)
데이터의 **'형태와 이름'**에 숨겨진 신호입니다.
- **Naming Conventions:** `user_id`, `created_at`, `arr_usd`와 같은 컬럼 이름의 패턴.
- **Schema Metadata:** 데이터 타입, Primary Key/Foreign Key 설정, 제약 조건 등.
- **Semantic Patterns:** 특정 도메인(예: 재무, 물류)에서 공통적으로 사용하는 약어나 명명 규칙.
- **에이전트 활용:** `Lexis`와 `Scribe`가 이 패턴을 분석해 비즈니스 용어와 매핑합니다.
    

### 4. 지식 시그널 (Knowledge Signals)
데이터 주변에 존재하는 **'부수적인 정보'**들입니다.
- **Existing Docs:** 과거에 누군가 작성했던 아주 짧은 주석, Slack에서의 대화 맥락, Jira 티켓 정보.
- **Tags & Labels:** 기존에 수동으로 붙여두었던 태그나 카테고리 정보.
- **에이전트 활용:** `Doc`이 이러한 파편화된 정보들을 취합하여 구조화된 README로 합성합니다.
