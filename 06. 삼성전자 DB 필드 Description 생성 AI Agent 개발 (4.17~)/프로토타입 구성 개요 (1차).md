# 프로토타입 구성 개요 (1차)

---

## 1차 범위 — 시나리오 A + B2-lite

### 1. 실행 요청

실행 단위와 범위 선택

- 실행 범위: 시스템 / 테이블 / 컬럼
- Description 존재 여부: 없는 것만 / 전체(있는 것 포함)
- API 문서는 테이블 단위로 request. 나머지 범위는 화면에만 구현하거나 기능 간소화 가능
- 트리거 방식: 버튼 실행 / API 호출

### 2. Source Connectors

원천 데이터(DB + 코드) 연결

- UI에 커넥터 상태 표시 (연결됨 / 연결 안 됨)
- 실제 연결은 옵션 — 준비된 데이터를 쓰거나, 가짜 데이터로 시연 가능
- 핵심은 "이 레이어가 DB와 코드 양쪽에 붙는다"를 화면에서 보여주는 것

### 3. Input Assets

입력 자산(용어집) 관리

- 용어집 업로드 / 카탈로그 동기화 / 직접 편집
- 현재 용어집 상태 표시 (등록 term 수, 최근 갱신 시점, 보강 후보 대기 건수)

### 4. 실시간 추론 경로 시각화 (데모 핵심)

1건 처리의 실제 과정을 스트리밍으로 표시

**추론 단계별 상태 메시지 (자연어)**

- "다른 시스템에서 같은 컬럼이 있는지 찾아보는 중입니다..."
- "용어집에서 연결된 비즈니스 개념을 조회하는 중입니다..."
- "스키마·샘플값으로 추론하는 중입니다..."
- "소스코드에서 라벨·Enum을 찾는 중입니다..."
- "판단 불가 — 단서가 충분하지 않습니다"

**B2-lite 메시지 (시연용 mock)** 실제 엔진은 백엔드 구현하지 않고 UI에서 표시만.

- "이 컬럼에 연결된 비즈니스 개념이 용어집에 없음 → 후보로 등록 중..."
- "소스코드에서 'PackageType' 발견"
- "용어집 보강 후보 검토 대기"

**한 테이블 돌려서 여러 케이스 보이도록**

- 타 시스템 재활용 성공 케이스 (L0)
- 용어집 비즈니스 개념 조회 케이스 (L1)
- 소스코드 맥락 활용 케이스 (L3)
- 침묵 케이스 (L-1)

내부 레벨 용어(L0/L1 등)는 노출하지 않음. 상태 메시지 중심.

### 5. 대량 처리 결과 탐색

배치 결과를 한 화면에서 탐색

- Confidence 배지 (High / Medium / Low)
- 출처 배지 (재활용 / 용어집 / 소스코드 / 샘플값) — 리스트 row에만 표시
- Confidence 필터 (High / Med / Low 토글)
- 컬럼명 검색

### 6. Low confidence 검토 워크플로우 + 출처 역추적

검토자가 결과를 확인하고 판단

- 컬럼 클릭 시 우측 패널에 상세 표시
- Description (한글 + 영문) + Confidence
- 출처 역추적 (구성 요소별 — 어느 term/소스에서 왔는지)
- 추론 과정 기록 (레벨별 성공/실패)
- 승인 / 반려 / 수정 / 에스컬레이션
- 잡 완료 후 판정 가능 (실행 중에는 조회만)

### 7. 반출

결과를 시스템 밖으로 내보내기

- 다운로드 (JSON/CSV)
- 카탈로그 반영 버튼
- 실제 연동까지는 옵션 — 화면에 보여주기 식도 가능

## 2차 예정 — 시나리오 B1 (용어집 Bootstrap)

용어집이 거의 비어 있는 Case 2 대응. 독립 플로우.

- 트리거: "용어집 Bootstrap" 실행 (수동)
- 인풋: 전체 소스코드 저장소 + DB 스키마
- 처리: 전수 스캔 → 비즈니스 개념 후보 추출 → term + 링크 대상 컬럼 목록 생성
- 결과: 용어집 term 후보 목록 → 일괄 검토 UI → 승인/거절
- 진짜 Vocabulary Builder 엔진 구현

## 3차 예정 — 시나리오 B2 완전 구현

1차의 B2-lite mock을 실제 엔진으로 교체.

- A 실행 중 자동 발동
- 백그라운드 용어집 gap 감지
- 검토 큐 관리 UI
- 근거 역추적 (어느 파일·어느 위치에서 발굴됐는지)

## 4차 예정 — 시나리오 C (변화 감지)

운영 레벨 지속 관리. 로드맵 2·3단계 체감.

- 스키마 diff 감지 → 영향 범위 계산
- 소스코드 변경 감지 → 관련 Description 재생성 큐
- 기존 vs 신규 비교 뷰

## 참고 (1차에서 뺀 기능)

- **진행 추적 (활성 Job·진행률·완료 이력)** — 과한 기능. 결과 탐색·필터링이 이 역할을 부분적으로 대체
- **전체 오버뷰 (누적 현황·Confidence 분포)** — 운영 레벨에서 필요, 1차는 단일 테이블 집중
- **출처 필터** — 1차 제거. Confidence 필터만 유지. 출처는 컬럼 row 배지로 표시
- **2차 에스컬레이션 (담당자·오너 라우팅)** — 조직별 거버넌스 프로세스 차이. UI에 버튼만 심고 실제 동작은 생략
