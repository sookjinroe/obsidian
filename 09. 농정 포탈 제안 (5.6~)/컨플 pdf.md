## 개요

- 오프라인 제안룸 구성에 따라, 제안서 작업의 표준화·접근권한·자산관리를 위한 **온라인 제안룸 환경** 구성 필요
- 신규 구축 및 지속적 확대에 필요한 **구조적 설계** 구현

## 구현 방향

- **영역 분리**: 활용성·확장성을 위해 공통 영역과 프로젝트 영역 구분
- **권한 통합**: 보안 강화를 위해 통합 권한체계 설계
    - 표준화된 권한 통합관리 설계
    - 포털시스템과 온라인 제안룸 권한 통합관리 우선 적용
- **소통 강화**: 산출물 현황관리·통합검색으로 조직 구성원 소통 강화 (포털 통합검색 + 제안룸 검색 이중화)

## 제안룸 구현 주요 내용

### 1. 공통 — 통합 권한 기반 사용자 분리

- 일반사용자 / 제안룸사용자 / 협력사 분리
- 통합 조직권한을 통한 포털시스템 + 온라인 제안룸 권한관리 적용
- **검색 차등**: 일반사용자(자료 유무·위치 확인 등) ↔ 제안룸사용자(정보 검색)

### 2. 영역 분리

- **메인/공통**: 제안룸 사용현황, 제안 템플릿·우수 제안서 전시
- **프로젝트**: 제안 프로젝트 중심으로 산출물 등록·관리

### 3. 보안 — 사업수주 및 지적재산 보호

- **승인 사용자**: **농협정보**·협력사 구분된 정보의 접근·다운로드 제한
- **일반 사용자**: 통합검색에서 자료 현황·관련 내용 확인 수준
- 사용 이력 등 관리 가능한 보안 수준 구현

### 4. 메인 — 제안서 전시 및 제안 현황 확인

- 우수 제안서·당해연도 제안 템플릿 전시 (사용자 가독성)
- 진행 중 제안룸의 진행 현황 확인
- 제안룸 내 검색 기능

### 5. 공통자산관리

- 템플릿·제안서의 통합 자산화
- 표준화된 제안 목차 제공 및 개선 (제안서 작업의 이정표)
- 템플릿 변화 이력, 유형별 제안서 관리

### 6. 프로젝트 제안룸 — 단위별 진행현황·산출물 관리

- **구성원**: 협력사 포함 제안룸 참여 직원 등록·수정
- **계획**: 표준 목차 기반 제안서 목차 구성·수정·삭제, 작업담당자 지정
- **실행**: 목차 항목별 결과산출물 등록
- **현황**: 제안기간과 항목별 등록 산출물을 고려한 진도현황 관리
- **산출물**: 등록 산출물 중 최종 산출물 확정, 변경이력 관리

### 7. 연계 — WITH 자원관리 확장

- 사용 접근 권한 **신청·승인·취소를 WITH로 연계**

### 8. 검색

- 통합검색과 제안룸 내 검색 기능 분리 구현
- 승인 권한 및 검색 위치에 따른 정보 권한 연계 (제한된 확인)

### 9. 관리

- 제안룸 사용 기간·사용 승인자·사용 이력 관리
- 사용이력: 산출물 등록·조회·다운로드 등 정보 제공

### 10. 자산화

- 프로젝트 제안룸의 확정된 최종 산출물 → 공통자산관리로 사업유형·규모·프로젝트 특성 고려하여 자산 등록

### 11. 데이터 관리

- 제안룸 생성 데이터는 **포털시스템과 동일한 별도 스토리지에 메타데이터로 별도 관리**

| #   | 신규 정보                           | 우리 설계에 미치는 영향                                                                           |
| --- | ------------------------------- | --------------------------------------------------------------------------------------- |
| 1   | **발주처가 농협** (3번 "농협정보")         | 공공·금융 성격. RFP 항목 매핑을 더 엄격하게, 보안 표현을 더 명확히 가져갈 필요                                        |
| 2   | **WITH 자원관리 연계** (7번)           | 제안룸 예약·승인·취소를 사내 시스템(WITH)으로 외부 처리 → **6.1 라이프사이클 관리가 훨씬 가벼워짐**. 자체 워크플로우가 아닌 연계 명세로 정리 |
| 3   | **메인 = "전시" 개념** (4번)           | 우리는 메인/공통을 한 영역으로 묶었는데, 자료는 **메인(전시) + 공통(자산 라이브러리)** 으로 더 분리. 1장 영역 정의 보완 필요           |
| 4   | **검색 차등 구체화** (1번)              | 일반사용자는 "자료 유무·위치 확인"만, 제안룸사용자는 "정보 검색" → **5.2 권한 기반 차등을 구체적 등급으로 표현** 가능               |
| 5   | **별도 스토리지 + 메타데이터 별도 관리** (11번) | 데이터 저장 아키텍처 명시. 1장 아키텍처에 "별도 스토리지" 한 줄 추가 필요                                            |
