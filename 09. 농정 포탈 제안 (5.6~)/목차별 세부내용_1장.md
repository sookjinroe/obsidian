## 1장. 전체 아키텍처

---

### 1단계 — 응답할 RFP 요건군

이 슬라이드는 **시스템 전체 구조**를 응답합니다.

| RFP 항목 | 내용                                    |
| ------ | ------------------------------------- |
| 1)-3   | 공통 영역과 프로젝트 영역을 분리한 구조로 설계            |
| 3)-1   | 메인/공통 영역과 프로젝트 제안룸으로 구분하여 설계          |
| 3)-2   | 메인/공통 영역에서 사용 현황, 제안 템플릿, 우수 제안서 등 제공 |
| 3)-3   | 프로젝트 제안룸은 프로젝트 단위로 구성, 산출물 등록·관리      |
| 보조 자료  | 메인(진입)과 공통(자산) 분리                     |
| 보조 자료  | 포털시스템 연계 (SSO·권한 동기화)                 |
| 보조 자료  | WITH 자원관리 연계 (예약·승인)                  |
| 보조 자료  | 별도 스토리지에 메타데이터로 별도 관리                 |

→ **이 슬라이드의 책임**: 영역 구분 / 영역 간 관계 / 외부 시스템 연계 / 데이터 저장 위치를 한 그림에 보여줌. → **다음 장에서 다루는 것**: 권한 동기화 디테일(2장), 자산 4유형·메타데이터 디테일(3장), 제안룸 동작(4장), 검색(5장), 운영(6장) — 여기서는 깊이 다루지 않음.

---

### 2단계 — 본문 컨텐츠 (응답 내용)

**(1) 영역 구분 설계** 온라인 제안룸은 메인 영역, 공통 영역, 프로젝트 제안룸 3개로 구성됩니다. RFP의 "메인/공통 영역"은 진입 성격(메인)과 자산 보관 성격(공통)을 분리해 운영합니다.

**(2) 메인 영역 — 진입 화면** 사용자가 시스템 진입 시 만나는 화면으로, 제안룸 사용 현황, 진행 중 제안룸 현황, 우수 제안서·당해연도 템플릿, 검색 진입점, 예약 현황을 제공합니다. 메인에서 공통 영역과 프로젝트 제안룸으로 진입합니다.

**(3) 공통 영역 — 자산 라이브러리** 운영자가 관리하는 자산 보관소이며 항상 존재합니다. 4유형 자산(표준 제안 목차·제안 템플릿·우수 제안서·최종 산출물)을 보유합니다.

**(4) 프로젝트 제안룸 — 사업 단위 작업 공간** 권한 있는 멤버만 접근하는 한시적 영역입니다. 사업 단위로 생성·종료되며 표준 목차 기반으로 산출물을 등록·관리·확정합니다.

**(5) 영역 간 관계**

- 공통 → 프로젝트 제안룸: 새 제안룸 생성 시 표준 목차가 자동 적용되며, 작업 중 템플릿·참고 자산을 다운로드해 활용합니다.
- 프로젝트 제안룸 → 공통: 확정된 최종 산출물은 운영자가 자산으로 등록합니다(자산화).

**(6) 외부 시스템 연계**

- 포털시스템: SSO 인증, 사용자·조직·역할 동기화 (디테일은 2장)
- WITH 자원관리: 제안룸 예약·승인·취소 연계 (디테일은 6장)

**(7) 데이터 저장** 시스템 데이터는 포털시스템과 동일한 별도 스토리지에 저장되며, 메타데이터는 검색·필터링을 위해 별도로 관리됩니다.

### 3단계 — 형식 결정

**판단**:

- 본문 컨텐츠가 7개 항목으로 많지만 모두 "시스템 전체 구조"의 부분들 → **도식 한 장에 통합**해야 의미 있음
- 표·화면은 부적합 (구조를 보여주는 게 본질)
- → **풀 도식 + 도식 캡션 + 짧은 텍스트 보조**

**도식에 표현할 요소**

- **중앙 — 시스템 본체** (3개 영역)
    - 상단: 메인 영역(진입 화면) — 사용 현황·검색·우수 사례·예약 현황 등 카드형 요소
    - 좌하단: 공통 영역(자산 라이브러리) — 4유형 자산 카드
    - 우하단: 프로젝트 제안룸(사업 단위 작업 공간) — 목차 트리·등록 상태 미니어처
- **상단 외곽 — 외부 시스템 2개**
    - 좌: 포털시스템 (라벨: SSO·권한 동기화)
    - 우: WITH 자원관리 (라벨: 예약·승인 연계)
- **좌측 외곽 — 사용자 (진입 화살표)**
- **우측 외곽 — 운영자 (자산 공급·생성 승인 화살표)**
- **하단 — 별도 스토리지** (라벨: 포털시스템과 동일 / 메타데이터로 별도 관리)
- **화살표 + 라벨**:
    - 사용자 → 메인 (진입)
    - 메인 → 공통 (자산 조회·다운로드)
    - 메인 → 프로젝트 제안룸 (권한자 작업 진입)
    - 공통 → 프로젝트 제안룸 (표준 목차 적용·자산 활용)
    - 프로젝트 제안룸 → 운영자 → 공통 (자산화)
    - 외부 시스템 → 시스템 본체 (연계)
    - 시스템 본체 → 별도 스토리지 (데이터 저장)

**짧은 텍스트 보조** (도식 옆 또는 하단 한두 단락)

> 온라인 제안룸은 메인 영역(진입 화면), 공통 영역(자산 라이브러리), 프로젝트 제안룸(사업 단위 작업 공간)으로 구성되며, 포털시스템(SSO)과 WITH 자원관리(예약·승인)에 연계됩니다. 모든 데이터는 포털시스템과 동일한 별도 스토리지에 메타데이터로 별도 관리됩니다.

## 우측 텍스트 컨텐츠

**공통 영역과 프로젝트 제안룸 분리로 재활용성과 보안성 동시 확보**
- 자산 라이브러리는 확정 자산을 보관, 프로젝트 제안룸은 진행 중 작업 공간으로 운영
- 표준 목차·자산은 공통 영역에서 제안룸으로 적용, 완료 산출물은 자산화를 통해 공통 영역으로 환류

**역할 기반 접근으로 영역별 차등 이용**
- 멤버(임직원)는 메인·공통 영역과 초대된 제안룸 이용, 게스트(협력사)는 초대된 제안룸만 이용
- 어드민은 자산 관리와 제안룸 생성 승인 담당

**포털·자원관리 시스템 연계로 일관된 운영**
- 포털 SSO·권한 동기화로 별도 인증 없이 이용
- 제안룸 예약·승인은 사내 자원관리 시스템(WITH)과 연계 처리
