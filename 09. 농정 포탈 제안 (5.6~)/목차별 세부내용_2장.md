## 2. 권한·접근통제

### 1단계 — RFP 요건군

| RFP 항목    | 내용                              |
| --------- | ------------------------------- |
| 1)-4      | 통합된 권한체계 설계·구현 / 포털시스템과 권한 통합관리 |
| 2)-1      | 일반사용자, 제안룸 사용자, 협력사 등 구분 관리     |
| 2)-2      | 포털시스템과 연계된 통합 권한관리              |
| 2)-3      | 사용자 권한에 따라 접근 정보 차등             |
| 4)-1      | 승인된 사용자만 접근 가능한 보안 체계           |
| 4)-2      | 사용자 유형별 접근·다운로드 제한              |
| 6)-1 (부분) | 프로젝트 단위 제안룸에서 구성원 등록 및 관리       |

---

### 2단계 — 본문 컨텐츠 (새 톤)

**포털 통합으로 별도 계정 없이 일관된 시스템 진입** SSO 기반 진입으로 포털과 동일한 방식으로 제안룸을 이용할 수 있습니다. 인사·조직 변동 시 권한이 자동 갱신되어 별도 관리 없이 정확한 접근 통제를 유지합니다.

**구성원 등록으로 제안룸별 접근 권한을 별도 부여** 각 제안룸에 구성원을 등록하여 접근 권한과 역할을 부여합니다. 협력사는 이 과정을 통해 특정 제안룸에 초대되어 임직원과 함께 참여합니다.

**접근 범위 표**

|사용자 유형|메인·공통 영역|개별 제안룸|
|---|---|---|
|임직원|접근 가능|구성원으로 등록된 제안룸만|
|협력사|접근 불가|구성원으로 등록된 제안룸만|
|운영자|전체 접근|전체 접근|

---

### 3단계 — 형식 결정

**도식 없음.** 1장 스타일 구조도는 공간 배치를 표현하는 데 적합하지만 권한·접근 제한 표현에는 맞지 않습니다.

**표가 메인 시각 자료.** 유형 × 접근 범위의 명확한 1:1 매핑이라 표 사용 기준 충족. 차등 접근이 한눈에 드러납니다.

**레이아웃:** 좌(텍스트 두 섹션) + 우(접근 범위 표)
