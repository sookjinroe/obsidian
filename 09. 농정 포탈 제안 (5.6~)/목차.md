## 1장. 전체 아키텍처

**장 개요** 전체 아키텍처는 메인/공통 영역과 프로젝트 제안룸의 이중 구조로 구성하고, 메인/공통 영역은 다시 메인(전시)과 공통(자산 라이브러리)으로 분리 운영하여 제안 자료의 체계적 관리·재활용, 제안 과정 협업·운영, 조직 내 지식공유 활성화를 통합 지원한다.

#### 1.1 시스템 영역 구조

- 자산 재활용성과 진행 중 보안성을 동시에 확보하기 위해 두 영역으로 분리 설계
    - 이중 영역 구조의 필요성 (재활용성 vs 보안)
    - 메인 영역 역할: 제안 현황·우수 제안서·당해연도 템플릿 전시, **제안서 검색 진입점, 제안룸 예약 현황 표시**
    - 공통 영역 역할: 표준 목차·템플릿·우수 제안서·최종 산출물 자산 라이브러리 (등록·검색·다운로드)
    - 프로젝트 제안룸 역할: 표준 목차 기반 산출물 등록·관리, 진도 표시, 최종 확정
- **RFP 매핑**: 1)-3, 3)-1, 3)-2, 3)-3

#### 1.2 영역 연계 구조

- 프로젝트 산출물이 공통 자산으로 이어지는 데이터 흐름과 통합 검색 기반 지식공유 채널을 정의, 향후 확장 가능한 구조로 설계
    - 영역 간 자산 흐름 (제안룸 산출물의 자산화, 3장 연계)
    - **운영자 공급 흐름**: 운영자(관리자)가 공통 영역에 표준 목차·템플릿·자산을 공급하고, 프로젝트 제안룸 생성을 승인 (6장 연계)
    - 통합 검색 기반 지식공유 (포털 통합검색 + 제안룸 검색 이중화, 5장 연계)
    - 데이터 저장: 포털시스템과 동일한 별도 스토리지에 메타데이터로 별도 관리
    - 향후 확장성 (영역 추가, 외부 시스템 연계 여지)
- **RFP 매핑**: 1)-1, 1)-2, 1)-3, 1)-5

## 2장. 권한·보안 체계

**장 개요** 권한·보안 체계는 포털 시스템과 통합된 권한 모델을 기반으로 사용자 유형별 차등 접근통제와 행위 이력관리를 일관되게 제공한다.

### 2.1 통합 권한체계

- 포털 시스템과 단일 사용자/역할 모델을 공유하여 권한 관리 일관성을 확보, 향후 타 시스템 확장 가능한 표준 모델로 설계
    - 포털 시스템 연계 (SSO + 권한 동기화)
    - 사용자 유형 정의: 일반사용자 / 제안룸 사용자(임직원) / 협력사 / 운영자
    - Role 기반 권한 모델 + 권한 매트릭스
    - 확장 청사진: 제안룸을 시작점으로 한 권한 통합관리 표준화
- **RFP 매핑**: 1)-4, 2)-1, 2)-2

### 2.2 접근통제 및 이력관리

- 영역·사용자 유형 기준 차등 접근통제와 주요 행위 이력 기록을 통합 운영하여 사업수주 및 지적재산 보호 요건 충족
    - **[A. 접근통제 정책]** 영역별 접근통제 / 사용자 유형 및 정보 유형별 접근·다운로드 제한 / 검색 결과 차등 (5장 연계)
    - **[B. 행위 이력관리]** 이력 기록 대상 행위(등록·수정·삭제·조회·다운로드·권한변경) / 로그 항목 표준 / 운영자 조회 (6장 연계)
- **RFP 매핑**: 2)-3, 4)-1, 4)-2, 4)-3

## 3장. 공통 자산 관리

**장 개요** 공통 자산 관리는 산출물을 분류·등록·갱신하는 체계를 구축하여 RFP 5번(공통 자산 관리)과 9번(메타데이터 관리)의 요구를 통합 대응한다.

### 3.1 공통 자산 구성 체계

- 자산을 활용 목적별 4유형으로 분류하여 등록·검색·갱신 단계에서 차등화된 관리 기준 적용
    - 자산 4유형 정의: 표준 제안 목차 / 제안 템플릿 / 우수 제안서 / 최종 산출물
    - 유형별 정의·활용 시점·관리 특성
    - 등록 권한: 운영자 권한으로 통합 관리
- **RFP 매핑**: 5)-1, 5)-2

### 3.2 자산 등록 및 메타데이터 관리

- 운영자가 자산을 공통 영역에 등록하고 메타데이터를 부여하여 검색 가능한 자산으로 관리
    - 자산 등록 흐름: 운영자가 공통 영역에 직접 등록 (메타데이터 + 산출물)
    - 메타데이터 스키마: 분류 메타데이터(사업유형·규모·특성) + 시스템 메타데이터(작성자·등록일·자산유형·버전)
    - 메타데이터 입력 표준 가이드 (분류 체계는 운영 정책 문서로 관리)
    - 등록 시 필수 항목 검증
- **RFP 매핑**: 5)-1, 9)-1, 9)-2

### 3.3 자산 변경 및 품질 관리

- 변경이력 추적과 우수 자산 갱신 사이클로 자산 신뢰성과 활용 가치 유지
    - 변경이력 관리: 자산 단위(등록·수정·삭제 / 작업자 / 시점)
    - 버전 관리: 새 버전 등록, 이전 버전 조회 가능
    - 우수 제안서 선정·갱신: 운영 정책으로 관리
    - 표준 제안 목차 갱신: 운영자가 새 버전 등록
- **RFP 매핑**: 5)-2, 5)-3

## 4장. 프로젝트 제안룸

**장 개요** 프로젝트 제안룸은 표준 목차 기반의 산출물 등록·관리 작업 공간이다. 제안 과정의 계획·실행·산출물 확정 흐름에 따라 3단계로 구성한다.

#### 4.1 제안 계획

- 제안룸 구성과 표준 목차 적용을 통한 제안 작성 기반 마련
    - 제안룸 생성 (운영자 승인 후, 6장 연계) 및 구성원 등록·역할 부여
    - 표준 목차 자동 적용
    - 항목별 담당자 지정
    - 제안 마감일 설정
- **RFP 매핑**: 6)-1, 6)-2

#### 4.2 제안 실행

- 목차 항목별 산출물 등록과 진도 표시로 제안 작성 운영
    - 목차 항목별 산출물 등록·수정·삭제
    - 첨부 버전 관리 (이전 버전 조회 가능)
    - 진도 표시: 목차 항목별 등록 상태 + 마감일 D-N
- **RFP 매핑**: 6)-3, 6)-4

#### 4.3 산출물 확정

- 확정 권한자의 최종 산출물 확정 처리와 변경이력 관리
    - 최종 산출물 확정 처리 (PL이 확정 권한자, 확정 후 변경 제한)
    - 변경이력 관리 (산출물 등록·수정·확정 행위 / 작업자 / 시점)
- **RFP 매핑**: 6)-5

## 5장. 검색 체계

**장 개요** 검색 체계는 통합검색과 제안룸 내 검색을 분리한 이중 채널 구조로 구성하고, 권한과 메타데이터를 기반으로 사용자별 검색 결과를 차등 제공한다.

#### 5.1 검색 이중화 구조

- 자산 발견과 작업 회수의 목적이 다른 두 검색을 분리하여 각 목적에 맞는 결과 제공
    - 두 검색의 목적·범위 정의 (통합검색 = 발견 / 제안룸 내 검색 = 회수)
    - 포털 통합검색: 공통 영역 자산을 포털에서 검색
    - 제안룸 내 검색: 진행 중 제안룸의 산출물 검색
- **RFP 매핑**: 1)-5, 7)-1

#### 5.2 권한·메타데이터 기반 결과 차등

- 사용자 권한과 메타데이터를 기반으로 검색 결과를 차등 제공하여 보안과 검색 정확도 동시 확보
    - 사용자 유형별 결과 등급 차등: 일반사용자(자료 유무·위치 확인 수준) / 제안룸 사용자(상세 정보 검색)
    - 권한 기반 결과 필터링 (2장 권한체계 연계 — 권한 없는 자산 미노출)
    - 메타데이터 기반 검색 필터: 분류 메타데이터(사업유형·규모·특성) + 시스템 메타데이터
- **RFP 매핑**: 2)-3, 7)-2

## 6장. 운영관리

**장 개요** 운영관리는 제안룸의 예약·사용·종료 라이프사이클과 제안룸 활동 이력 조회를 운영자 권한으로 통합 운영한다. 사용 권한 신청·승인·취소는 사내 자원관리 시스템(WITH)과 연계하여 처리한다.

#### 6.1 제안룸 라이프사이클 관리

- 제안룸 예약·승인부터 종료까지의 라이프사이클을 운영자 권한으로 일관 관리
    - 라이프사이클 단계: 예약 → 승인 → 활성 → 종료
    - WITH 자원관리 연계: 사용 권한 신청·승인·취소를 WITH로 처리 (자체 워크플로우 미구현)
    - 사용 기간 관리 (기간 설정, 만료 알림)
    - 사용 이력 조회 (제안룸 단위 신청·승인·종료 이력)
- **RFP 매핑**: 8)-1

#### 6.2 활동 이력 조회

- 제안룸 활동 이력을 운영 관점에서 조회하여 활동 모니터링과 보안 감사에 활용
    - 활동 이력 조회 (제안룸별 / 사용자별 / 행위 유형별)
    - 활성 제안룸 현황 조회
    - 보안 감사 및 운영 관리 활용 (2장 행위 이력 데이터 활용)
- **RFP 매핑**: 8)-2
