## 4.1 제안룸 구성

### 1단계 — RFP 요건군 + 본질

|RFP 항목|내용|
|---|---|
|6)-1|프로젝트 단위 제안룸에서 구성원 등록 및 관리|
|6)-2|표준 목차 기반 제안서 구성·수정·삭제·작업담당자 지정|

→ **본질**: 제안룸에 들어갈 사람과 작업할 골격(목차·담당자·기간)을 갖춘다.

---

### 2단계 — 본문 컨텐츠

**구성원 등록으로 작업 참여자 구성**

- PL이 구성원을 등록·관리하여 작업 참여자를 명확히 정의합니다 (2장 권한체계 연계)
- 임직원과 협력사를 함께 등록하여 외부 협력이 필요한 제안에도 대응합니다
- 진행 중 구성원 추가·변경이 가능하여 사업 특성·일정에 따라 유연하게 운영합니다

**표준 목차 자동 적용으로 작업 골격 즉시 구성**

- 자산 라이브러리의 표준 목차가 자동 적용되어 별도 설정 없이 작업을 시작합니다 (3장 연계)
- 목차 항목을 사업 특성에 맞게 추가·수정·삭제하여 제안서를 구성합니다

**항목별 담당자·기간 설정으로 작업 책임 명확화**

- 목차 항목별로 담당자를 지정하여 여러 구성원이 동시에 작업에 참여합니다
- 제안 마감일 설정으로 작업 일정의 기준점을 마련합니다

---

### 3단계 — 형식 결정

**a.** 텍스트로 명료한가 → 가능하나 시각화 가치 있음. 구성원·목차·담당자가 모두 "제안룸 설정 화면"에서 이루어져, 화면을 보여주면 평가자에게 직관적.

**b.** 시각 자료 → 화면 2개. 6)-1(구성원)과 6)-2(목차·담당자)가 별개 기능이라 화면도 분리해서 보여줌.

**c.** 형태 → 좌(화면 2개 세로 배치) + 우(텍스트 3섹션)

**d.** 슬라이드 최종 구성

## 4.2 제안 작업 운영

### 1단계 — RFP 요건군 + 본질

| RFP 항목 | 내용                      |
| ------ | ----------------------- |
| 6)-3   | 목차 항목별 산출물 등록·관리        |
| 6)-4   | 제안 기간·산출물 등록 현황 반영 진도관리 |
| 6)-5   | 최종 산출물 확정 및 변경이력 관리     |

→ **본질**: 산출물을 등록하고 진도를 보며 최종 확정까지 가는 작업 흐름.

---

### 2단계 — 본문 컨텐츠

**항목별 산출물 등록·버전 관리로 작업 결과물 통합 관리**

- 담당자가 목차 항목별로 산출물을 등록·수정·삭제하여 분담된 결과물을 한 공간에 모읍니다
- 첨부파일은 자동 버전 관리되어 이전 버전 회수와 변경 추적이 가능합니다

**등록 상태·마감일 가시화로 작업 진도 실시간 파악**

- 항목별 등록 상태(미등록/등록/확정)와 마감일 카운트다운(D-N)을 함께 표시하여 PL이 지연 항목을 즉시 식별합니다
- 전체 등록률을 통해 제안 완성도를 한눈에 확인합니다

**최종 확정과 변경이력으로 산출물 신뢰성 확보**

- PL의 최종 확정 후에는 변경이 제한되어 확정 시점의 산출물 무결성이 유지됩니다
- 등록·수정·확정 모든 행위가 작업자·시점과 함께 이력으로 기록되어 추적과 감사 대응이 가능합니다
- 확정 산출물은 운영자 검토를 거쳐 자산 라이브러리에 등록됩니다 (3장 연계)

---

### 3단계 — 형식 결정

**a.** 시각 자료 → 작업 화면. 목차 트리 + 등록 상태 + 담당자 + D-N + 등록률이 한 화면에서 보임. 4.2의 본질을 직관적으로 전달.

**b.** 4.1 화면과 차별화 → 4.1은 "구성 시점"(미등록·담당자만), 4.2는 "작업 진행 중"(등록 상태 ○✓●, 진도, 등록률).

**c.** 형태 → 좌(작업 화면) + 우(텍스트 3섹션)

**d.** 슬라이드 최종 구성
