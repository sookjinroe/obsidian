## 1장. 전체 아키텍처

**핵심 메시지** "왜 이중 영역 구조인가" — 재활용성과 보안의 트레이드오프를 해결하면서 **조직 내 지식공유를 활성화**하는 설계

**담을 내용**

- 도입부: 시스템의 상위 가치 — 제안 협업 효율화 + 조직 내 지식공유 활성화
- 설계 원칙: 공통/프로젝트 분리의 근거 (자산 재활용 ↔ 진행 중 보안)
- 영역별 역할 정의
    - 메인/공통 영역: 제안룸 사용 현황, 표준 목차, 우수 제안서, 템플릿 라이브러리
    - 프로젝트 제안룸: 프로젝트 단위 작업 공간, 산출물 등록·관리
- 영역 간 데이터 흐름: 프로젝트 산출물 → 자산화 → 공통 영역 (선순환 구조)
- 논리 아키텍처 구성도
- 향후 확장성 고려: 영역 추가 여지

**RFP 매핑**: 1)-1, 1)-2, 1)-3, 1)-5, 3)-1, 3)-2, 3)-3

## 2장. 권한·보안 체계

**핵심 메시지** "한 번 정의된 권한이 모든 영역에 일관되게 작동" — 포털 통합 + 사용자 유형 차등

**담을 내용**

- 통합 권한체계 설계 원칙: 포털과 단일 사용자/역할 모델 공유
- 사용자 유형 정의: 일반사용자 / 제안룸 사용자(임직원) / 협력사 / 운영자
- 권한 매트릭스: 영역(공통/프로젝트) × 행위(조회/등록/수정/다운로드) × 사용자 유형
- 포털 시스템 연계: SSO + 권한 동기화 (입·퇴사 시 권한 변동 반영)
- **확장 청사진**: 본 사업의 통합 권한관리 모델은 향후 타 시스템 확장에도 적용 가능한 표준 모델로 설계
- 사용자 유형별 정보 접근 및 다운로드 제한 정책
- 행위 이력관리: 등록·조회·다운로드 등 주요 행위 로그

**RFP 매핑**: 1)-4, 2)-1, 2)-2, 2)-3, 4)-1, 4)-2, 4)-3

## 3장. 공통 자산 관리

**핵심 메시지** "끝난 제안서가 다음 제안의 재료가 되는 선순환" — 자산화 + 메타데이터로 검색 가능한 자산으로 변환

**담을 내용**

- 자산 분류 체계: 표준 목차 / 제안 템플릿 / 우수 제안서 / 최종 산출물
- 표준 제안 목차: 초기 정의 + 지속 개선 체계
- 자산 등록 워크플로우: 프로젝트 종료 → 자산화 검토 → 메타데이터 부여 → 공통 영역 등록
- 메타데이터 스키마: **사업유형, 사업규모, 프로젝트 특성**(RFP 명시 항목) + 향후 확장 가능 구조
- **메타데이터 운영 모델**(가벼운 버전): 입력 표준 가이드 + 등록 시 검증 룰 + 운영자 점검 주기
- 자산 변경이력·버전 관리
- **자산 품질 관리**(가벼운 버전): 우수 제안서 선정 기준 + 갱신 주기를 운영 정책으로 문서화

**RFP 매핑**: 5)-1, 5)-2, 5)-3, 9)-1, 9)-2

## 4장. 프로젝트 제안룸

**핵심 메시지** "표준 목차를 따라가면서도 프로젝트별 변형을 수용하는, 계획·실행·산출물 관리의 작업 공간"

**담을 내용**

- 제안룸 구성원 등록·역할 부여
- **① 제안 계획 단계**: 표준 목차 적용 → 프로젝트별 수정·삭제·추가 → 작업담당자 지정 → 일정 수립
- **② 실행 단계**: 목차 항목별 산출물 등록·버전 관리 + 진도 관리(제안 마감일 + 항목별 작성 상태 + 담당자별 진행률)
- **③ 산출물 확정 단계**: 확정 권한자가 최종 산출물 확정 → 변경이력 관리 → 자산화 후보로 등록(3장 흐름)

**RFP 매핑**: 1)-1(계획·실행·산출물 키워드), 6)-1, 6)-2, 6)-3, 6)-4, 6)-5

## 5장. 검색 체계

**핵심 메시지** "두 검색은 목적이 다르다" — 발견(discovery)과 회수(retrieval)의 분리, **조직 지식공유의 핵심 채널**

**담을 내용**

- 두 검색의 정의와 차이
    - 포털 통합검색: 자산 발견 — "비슷한 제안 사례 있나?" → 조직 내 지식공유의 출발점
    - 제안룸 내 검색: 작업 회수 — "그 자료 어디 뒀더라?"
- 통합검색: 자산화된 제안 자료를 포털 검색 결과에 노출 (3장 자산화 결과 활용)
- 제안룸 내 검색: 해당 프로젝트 컨텍스트 안에서의 빠른 검색
- 권한 기반 결과 차등 (2장 권한체계가 검색 결과에 적용)
- 메타데이터 기반 필터: 사업유형·규모·특성 등으로 검색 좁히기 (3장 스키마 활용)

**RFP 매핑**: 1)-5, 7)-1, 7)-2

## 6장. 운영관리

**핵심 메시지** "제안룸 라이프사이클 전체를 추적·관리"

**담을 내용**

- 제안룸 라이프사이클: **예약 → 승인** → 활성 → 종료 → 자산화 → 보존
- 제안룸 예약·승인 워크플로우 (운영자 권한)
- 사용 기간 관리: 기간 설정·만료 알림·연장 신청
- 사용 이력 관리: 제안룸 단위 (예약·승인·종료 기록)
- 활동 이력 조회: 산출물 등록·조회·다운로드 등 (2장 이력관리 데이터를 운영 관점에서 조회)
- 운영 조회 화면: 활성 제안룸 현황·사용 통계

**RFP 매핑**: 8)-1, 8)-2
